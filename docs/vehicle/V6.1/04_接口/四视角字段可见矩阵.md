# 四视角订单DTO与字段裁剪规范 V6.0

本规范是本轮针对契约缺口作出的技术设计，不把历史通用Order实体作为API。OwnerOrderView、DriverOrderView、StationOrderView、AdminOrderView分别有独立字段白名单；列表采用对应Summary。

## 强制规则

订单详情/列表/动作回包均不得先序列化实体后靠前端隐藏。跨参与方交接/取消回包用OrderActionReceipt最小事实，前端再GET本视角详情。交接码只从特定持码接口返回，所有订单视图均不含code。任意视角不返回密码、微信密钥、完整证件、证件密文、存储对象键、内部台账/安全审计。

司机ACTIVE_ASSIGNMENT必须绑定自己的有效assignmentId；邀约未接受时只展示邀约摘要。承接结束立即采用HISTORY，地址/坐标/联系人父对象必须null；历史证据的查看再经业务允许时间及敏感文件接口校验。站点界面不返回上门住址、客户付款金额、司机报酬。后台默认也不获得财务或住址字段。

空值与缺字段：required+nullable字段在无权/未产生时明确null；未在本视角Schema声明的字段必须完全省略。列表Summary不自动包含详情字段。公开审核文字由服务端专门生成/选取，不直接拷贝内部意见。
