# 认证、权限、错误与路由 V6.0

## 路由与退出
新业务Controller显式映射/api；server.servlet.context-path保持/；代理原样转发URI。OpenAPI servers只有域名，不重复附/api。直连例：GET http://localhost:8080/api/common/profile；代理例：GET https://你的域名/api/common/profile。后台旧/system、/monitor等仍走原框架，仅网络隔离不等于业务鉴权。

MINI唯一退出：POST /api/common/session/logout，支持allDevices。未开发的/api/common/logout已从活动契约删除，不实现别名、不做迁移。ADMIN沿用现有xinyi /logout（本包不重建框架认证）；不能将小程序token送到后台退出。该外部框架路径由仓库集成测试确认，不把它添加成双域业务接口。

## 授权表达
主契约每个操作有x-authorization，明确认证域、当前角色、能力/功能码与数据范围。x-permission只允许注册的biz:资源:动作；不是“本人”等自然语言。x-capability是C端能力；本人、本站、承担费用主体在 x-authorization.scope 中表达。SERVICE/公开回调不冒充业务角色。注册表覆盖每个操作及字段级权限；返回的permissions/capabilities只供UI展示，服务端仍逐次校验。

读接口使用query/list等查询功能；新增、编辑、发布、审核、导出分别授权。使用biz:order统一单数。跨站是组织/部门/显式站点的交集；本人司机账单必须校验driver与费用主体；没有范围fail-closed。错误403表示已确认无权；未知/不可见目标使用统一404避免资源枚举。基础令牌错误401、权限权威源故障503，不能因缓存故障放行。

## 共享 common 端点授权（R6）
`/api/common/**` 中 handover、files、uploads、employee-binding 等端点为多调用方共享（车主 MINI / 员工 MINI(STATION 视角) / ADMIN 后台代办），在 OpenAPI 以 `x-capability` 表达 C 端能力，在权限注册表以 `biz:*` 表达后台功能权限。两者不是“任一满足即放行”，服务端按调用方认证域选择判据并叠加四要素，全部成立才放行：

1. 能力/功能权限：MINI 调用方校验 `x-capability`（如 COMMON_FILES_ACCESS、COMMON_HANDOVER_*）；ADMIN 调用方校验对应 `biz:*` 功能权限码。注册表 `biz:*` 与 yaml `x-capability` 是同一能力在两个认证域的登记，**以调用方所属认证域的判据为准**，不跨域借用。
2. 数据范围：本人/本站/承担费用主体范围由 `x-authorization.scope` 表达；handover 区分 HOLDER_ONLY（持码方读 secret）与 VERIFIER_ONLY（核验方仅提交，403 拒绝读码）；files/uploads 校验对象归属与业务绑定。
3. 状态：交接阶段/文件 READY/绑定凭证有效等前置状态必须满足。
4. 认证域：MINI token 不得用于 ADMIN 判据，反之亦然；员工 MINI(STATION) 取“真实员工有效权限 ∩ 小程序检测端允许动作”，不把后台通配权限复制给 MiniPrincipal。

任一要素不成立即拒绝（无权 403、未知/不可见目标统一 404、状态/版本冲突 409），不以“能力码匹配”单独放行。`employee-binding` 的签发(ADMIN, biz:employeebinding:issue)与消费(MINI, 能力 EMPLOYEE_BINDING + 一次性凭证)分属不同认证域与不同人，凭证仅此次返回、库内只存摘要。

## 普通业务错误
HTTP真实状态与body.code相同；errorCode是稳定业务枚举；msg是可读说明，客户端不得用中文msg分支。requestId用于诊断，不包含机密；retryable指可以在指定动作策略下恢复，不表示允许盲目重做支付。
字段错误在data.fieldErrors；选中集合冲突在data.conflicts，不能返回未授权目标详情；交接照片和错误次数在限定字段。429与503提供Retry-After及对应秒数。400为格式/类型，422为合法格式但领域前置不满足，409为状态/版本/幂等/占用冲突。
所有普通业务错误通过components.responses复用；接口声明的业务码见x-error-codes，字典见错误码表.json。404只在有对象查找语义时声明，不为凑数量给所有列表填404。

第三方notify不套业务ApiError。微信支付成功返回204空体，失败保留渠道约定体；验签前不记录可信业务。连接层网关也可能返回HTML/无体5xx，客户端网络层要兜底不可解析响应；不假装应用错误Schema能约束所有外部设备。
