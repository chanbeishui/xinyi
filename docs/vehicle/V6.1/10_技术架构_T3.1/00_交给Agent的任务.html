读取 taskctl next → 认领已就绪任务 → 实现 → 运行本任务测试 → 修复 → 保存证据和独立复核 → 继续下一项。78任务包含全部已确认功能；不因只做首个切片就省略对账、售后等后续范围。

开发任务前置达到 IMPLEMENTED 可继续编码；VERIFIED 要求实际测试，REVIEWED 要求独立复核。验证环境不可用时保存 VERIFICATION 阻塞，不把全部编码标为失败，也不报测试通过。当前运行结束时更新 RESUME.md 和下一条命令；工具不会自动启动后台 Codex 会话。

6. 不得改动的业务与安全规则

实际归还立即释放指定承接，不等后续确认/核价/退款；已接车取消先审批待返还，实还后取消；未接车代驾取消承接仍原单重派。对账按 selectedEntries 明确勾选同人同主体组单，日期只筛选，行内核价和独立整单复核保留，确认后只调差，付款凭证独立核实。无钱包/自动转账。

保留既有 sys_user 多部门、auth_version、安全 outbox、功能与数据权限；小程序 MiniPrincipal 必须新建并隔离，不伪装 LoginUser。不全局 permitAll，不把新接口金额和旧sys ID一并改类型。父/子版本、快照、幂等、私有证据和敏感字段裁剪仍以主契约与T3.1为准。

7. 分层阻塞与完成判断

CONTRACT只阻受影响接口；POLICY只阻相应正式规则启用；CREDENTIAL只阻真实供应商验证；ENVIRONMENT针对真实失败命令；ACCESS不允许绕过。开发夹具使用明确测试数据，不能擅定真实费率、补偿或准入政策。

CODE_COMPLETE、LIVE_VENDOR_VERIFIED、RELEASE_APPROVED分别记录。G01要求真实 API→Service→Mapper→MySQL、完整前端、恢复与安全测试，并有全量覆盖与独立复核；绝不能用固定Ack、假页面和文件数量代替。
