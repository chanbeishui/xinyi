# 任务执行、覆盖与完成判据

## 1. 全功能分解

`tasks.json`有78个具名任务：75个开发/集成/交付任务、3个真实环境发布门槛。每项有前置、产物、负向条件、精确API operationId、画板、表、原用例ID及代码落位。`task_packets`是由主规范派生的任务输入，不允许与主契约分别修改。

249个业务接口（包含本轮补齐的公开配置读取）、287画板、66表和298原验收用例均有唯一交付责任任务。唯一主责任不等于只在一个任务测试：跨角色/资金/权限同时映射T01–T08综合测试，见测试追溯矩阵。

## 2. 实施与验证两条队列

NOT_ASSESSED→PLANNED→IN_PROGRESS→IMPLEMENTED→VERIFIED→REVIEWED。BLOCKED有具体分类、错误、受影响任务、已可做任务、恢复条件。已有代码先核对，不能直接批量标REVIEWED。

`taskctl next`优先给出依赖就绪的实施任务；已实现项目进入验证/复核队列。集成人为唯一账本写入者，其他Agent提供patch和证据，避免JSON并发覆盖。依赖达到IMPLEMENTED仅放行后继编码，不等于可以发布或跳过前置失败。

示例（路径需是实际本机已存在证据，不复制示例假报告）：

```bash
python docs/vehicle/V6.1/12_工程执行/taskctl.py set --repo . --task A02 --status IN_PROGRESS
python docs/vehicle/V6.1/12_工程执行/taskctl.py set --repo . --task A02 --status IMPLEMENTED --evidence docs/implementation/vehicle/evidence/A02.json
python docs/vehicle/V6.1/12_工程执行/taskctl.py set --repo . --task A02 --status VERIFIED --evidence docs/implementation/vehicle/evidence/A02.json
python docs/vehicle/V6.1/12_工程执行/taskctl.py next --repo .
```

证据至少有代码路径、实际命令、退出码、测试数量/跳过数、JUnit报告和独立审查。工具能校验格式和文件存在，不能自行证明报告真实；禁止伪造PASS文本骗过账本。

## 3. 各类任务完成

|任务类别|必须具备的证据|
|---|---|
|E00/E01|实勘记录/契约测试；不是生产业务测试|
|E02/E03/E04/E05/E08|工具版本、实际环境健康/建库/构建/CI运行；库不能仅解析SQL|
|Service/API任务|实际Controller→Service→MyBatis→MySQL HTTP测试，至少正常、越权/错误、重复/冲突；有前端的还需可操作|
|后台任务|可控Clock、真实DB任务领取/租约/重启恢复，不以sleep一天或调用私有方法改状态替代|
|T类综合验收|按跨步骤数据链跑，前一步ID/版本/金额自然传到后一步；断言实际DB与拒绝的无副作用|
|G01|全部覆盖行真实路径、测试、独立复核；查残留空实现和固定数据；无遗漏|
|L类上线|真实供应商与微信真机、政策主体、灰度与备份恢复另证；不因本地模拟通过而通过|

## 4. 防止“看似完成”

接口代码文件存在、Swagger出现路由、空表有索引、返回固定Ack、用localhost变量模拟订单、截图齐全，均不算功能实现。对账金额取真实台账，关闭订单要可信渠道结果，司机释放要精确assignment匹配、事务与并发测试。

PC和小程序都必须实现，不允许后端交付后默认“前端按原型自行做”。基础开发先纵向切片，最终G01审核所有页面/状态；不能借MVP删除本包已确认功能。

## 5. 接续交付

每次停止都输出完成taskId、修改文件、实跑命令和失败、当前Git状态、下一taskId、具体恢复命令。保留当前任务实际进度，不重新清库或生成第二套模块。工作树不干净不是强制停止理由，但不得覆盖与本任务无关变更；文件冲突才作为局部ACCESS/CONTRACT处理。


## 实现阻塞与验证阻塞分开记录

已完成代码但数据库/供应商测试环境不可用：保持IMPLEMENTED，使用note-blocker --layer VERIFICATION记录具体失败与恢复条件，不能降成实现BLOCKED使无关后续代码全部锁住，也不能标VERIFIED。真正契约不清、权限不足无法继续写代码才以IMPLEMENTATION阻塞任务；生产资质用RELEASE。

```bash
python docs/vehicle/V6.1/12_工程执行/taskctl.py note-blocker --repo . --task E03 --layer VERIFICATION --reason "ENVIRONMENT: Docker不可用；恢复后执行db-test"
```

下游只能基于IMPLEMENTED继续编码，不能借此宣称集成成功；G01仍要求全部测试和独立复核。E00的实勘、E02工具环境和E04/E05构建可使用checksRun与WORKSPACE_OBSERVATION/ENGINEERING_ENVIRONMENT/BUILD证据类型，不伪造单元测试数量；API业务任务仍必须LIVE_HTTP_MYSQL。
