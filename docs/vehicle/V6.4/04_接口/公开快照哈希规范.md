# 司机确认的公开快照哈希 V6.4

snapshotHash并非秘密。它必须证明司机实际看到的服务和金额版本，不得覆盖内部草稿拟价、复核意见或银行原始凭证。

1. 构造数组 `["VI-STATEMENT-PUBLIC-1", statementId, statementNo, driverId, payorEntityId, currency, revisionText, lines]`。
2. 每行数组为 `[lineId, entryId, assignmentId, orderNo, plateNo, serviceEndedAtUTC, amountFenText, pricingExplanation]`。ID、版本和金额均十进制字符串；非负ID无前导0；金额允许已批准负调差。时刻固定`YYYY-MM-DDTHH:mm:ss.SSSZ`。所有必需文本按原Unicode保存，不trim、不本地化、不NFC改写；若业务要归一化，在发布前完成。
3. lines按十进制lineId的数值升序排序，不按字典序。只包括当次明确选中并发布的成员。
4. JSON紧凑编码UTF-8；无BOM、无多余空格。非ASCII不转义；必须转义引号、反斜线和控制字符，不转义斜杠；限制输入不含未配对UTF-16代理项。数组顺序固定，避免对象键排序差异。
5. 对上述字节做SHA-256，输出小写hex。测试夹具给出原字节及摘要。服务器生成；客户端只回传，不要求前端自行哈希证明可信。
6. paymentSummary、当前状态、确认时间及行version不在内容hash中；付款变化不改内容。revision与成员/金额一起递增；请求同时携带expectedVersion、expectedRevision、snapshotHash。内部快照单独保存internal hash，不得混用。
7. 确认事务加载SENT公开快照，核对本人、版本及hash，CAS/父行锁成功后记确认与唯一费用结转。后台同时撤回只能一个提交成功。哈希不是鉴权令牌，知道他人hash仍不能访问或确认。
