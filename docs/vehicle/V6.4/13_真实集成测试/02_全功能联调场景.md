# 全功能真实联调：场景、前置、输出及数据库断言

每条场景由真实业务API串联，使用上一步返回的ID/version/hash/金额。基础夹具不直接构造终态订单。下面是必须实现的测试清单，执行责任在T01–T08，不是本轮已运行结果。

|IT02 多设备与员工自动关联|两个设备、唯一匹配员工A|后台先给未登录员工配置站点→微信手机号核验→自动关联→默认车主→切站→撤权→切回OWNER|不创建旧申请/凭证；重复核验幂等；暂停不能靠重登绕过；context与auth_version权威；ACCOUNT1非超管|
|IT03 首次预约四组合|车/地址可以已有或草稿|先时段→新地址→车型→quote→条款→order|4组合均合法；双传/缺组/null/伪造金额拒绝；草稿不自动写地址簿|

|IT08 未接车解除|司机A接单未取车|取消承接→释放A→邀请B→B接受|同orderNo和原paid记录；A新任务不被旧事件清除；无重复满额报酬|

|IT10 检测双端并发|车在站、资料复核完成|PC和station同时登记结果→另一方冲突→更正申请/审核|有效结果唯一；不合格也可返还；未检测取消不造PASS结果|
|IT11 归还与旧事件|A实际归还后接B|归还A→释放→接B→A服务自动完成/退款回调|B占用保持；A费用异步失败不回锁；照片完成但未交车不释放|
|IT12 已支付未接车取消|付款成功未接车|统一申请→一次审核→退款受理→回调/查询|同申请审核一次；可退余额含预留；重试同refundNo；客户钱不改司机报酬|
|IT13 已接车取消|driver或station持车|申请→批准WAIT_RETURN→现场返还→正式取消→退款|批准不释放；未还不假终态；返还后不再二审；无需伪造未发生照片节点|
|IT14 正常异常与服务确认|归还后/履约中|异常上报/争议→处理→24h完成/服务确认/评价|不恢复事故保险；争议暂停autoComplete但不占已释放司机；日志完整|
|IT15 明确勾选组单|多日期结束任务与NULL费用|跨页选1/3/5→预览→生成draft|未选仍待对账；每entry一有效allocation；重叠集合整批409；同日期不重叠两单均可|
|IT16 核价与复核|草稿含待价|填写/修改60→70→65→独立复核→send|最终65，非叠加；同人不能复核；移出/增加使旧hash失效；空价不发送|
|IT17 确认版本竞争|已发送|撤回与本人确认同时→差异/重发|只一成功；旧public hash不能确认；MINI不返回内部拟价与复核字段|
|IT18 付款凭证|已确认账单|录入部分凭证→另人核实→第二次足额|待核实预留不计已付；同主体流水唯一；超额拒绝；0元无需凭证；不分摊行付款|
|IT19 已确认调差|账单已确认/已付|原行调差→独立审批→后续账单|原账不覆盖；差额来源永久去重；负额不自动追收|
|IT20 隐私与导出|有权限/撤权两用户|申请访问→审批→生成导出→撤权→下载|生成与下载二次鉴权；未授权数量不泄露；CSV公式注入防护|
|IT21 文件/OCR与失败恢复|文件真字节存储|签名上传→元数据核验→OCR低置信→人工复核|错误类型/大小/归属/过期拒绝；失败可重传不覆盖已封存证据|
|IT22 培训活体处罚|普通申请人|课程版本→playback→attempt→submit→face-session→审批→处罚→申诉|不发标准答案；墙钟进度约束；本人能获得penaltyId；供应商回报未知非通过|
|IT23 任务恢复与审计|两个worker、outbox失败|领取→终止worker→租约过期→重领→业务幂等|不双退款、双释放、重复入账；审计不含Token/证件原文|

## 负向请求与SQL证据

常用断言查询只在隔离DB按已授权测试ID执行，下面不替代完整测试实现：

```sql
SELECT COUNT(*) FROM vi_driver_occupancy WHERE driver_id=?;
SELECT holder_type,holder_id,order_id FROM vi_driver_occupancy WHERE driver_id=?;
SELECT version,fulfillment_status,cancel_status FROM vi_order WHERE id=?;
SELECT status,revision,amount_fen,unpriced_count,published_hash FROM vi_driver_statement WHERE id=?;
SELECT table_name,column_name,extra FROM information_schema.columns
 WHERE table_schema=DATABASE() AND generation_expression<>'';
```

财务实际字段和约束以主模型为准，禁止把测试查询拼接客户端字符串。所有关键写失败再读确认无副作用。事务性失败与验证码错误次数应有不同持久化边界，避免回滚业务时把攻击计数回滚。
