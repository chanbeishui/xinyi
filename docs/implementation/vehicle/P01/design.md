# P01 预支付设计

以订单原始 receiver_dept_id（公司收款主体）为权威，不从当前用户部门、客户端参数或当前站点部门重新推断。OWNER 仅可操作本人订单，事务在目录授权锁后再次加载账户、会话、安全代际、角色和 contextVersion。无部门/授权写入，不新增 auth_version 变更源。后台配置权限沿用 X01 多部门控制。

POST prepay 只接受支付单 expectedVersion 和当前策略 expectedPolicyRevisionId，以及 UUID 幂等键。提前实现 X02 所属 GET payment-options 以提供这两个权威值；没有将 X02 整体标为完成。预支付金额、openid、AppID、商户号、商户单号、截止时间均从服务端取值。新商户号为32位随机编号；历史超长编号仅在 UNSELECTED/PENDING、无交易/商户/方式锁/实付时前向回填，其他异常报告不改写。

第一事务锁定订单和支付单，核对状态、额度保留和原截止时间，读取主库已发布配置；第一次选择微信锁定原商户身份、配置版本与加密请求快照。相同幂等键只缓存支付单ID，始终重新鉴权和检查截止时间，不缓存可直接付款的敏感响应。外部请求使用30秒租约，先提交 UNKNOWN/REQUESTING，再离开数据库事务执行网络调用；不在网络等待期间持有业务锁。

使用官方 wechatpay-java 0.2.17 完成请求签名、微信响应验签和小程序唤起签名；支持微信支付公钥和平台证书。响应头按HTTP大小写不敏感规则规范名称，保留原值，重复关键头拒绝。禁止自动网络重试和重定向，共用有超时的连接池。仅 integration/test 可显式配置 http://127.0.0.1:端口 协议替身；非生产且未配置替身时拒绝，不能落到真实供应商。生产不接受替身配置。回调由 HTTPS 部署 origin 加固定路径生成。

响应或失败在第二事务按租约与版本落库，审计/outbox同事务；失败/超时/验签失败保留UNKNOWN与原方式。成功仅将加密 prepay_id 保存为READY/PENDING，绝不写 paid_fen 或履约成功。外部返回与支付成功/关闭竞态时CAS拒绝覆盖。outbox失败时全部回滚，租约到期后以同一个商户单号、原始请求和截止时间恢复。已签发预支付可重用；停用微信开关阻止新的外部预下单，不能通过换键切换线下或延长付款期限。

原商户身份保持不可变，同主体凭据轮换读取当前已发布凭据；历史身份不跟随新商户。根密钥、秘密可用性、发布状态失败均关闭操作。请求快照与prepay_id使用X01版本化AES-GCM主密钥，AAD绑定支付单与用途；不写审计/outbox/普通幂等缓存，不在浏览器持久化。SDK日志关闭，测试客户端请求体日志关闭；仅提交脱敏测试摘要。

页面从订单详情进入；金额、截止和支付结果来自服务端。微信客户端成功只显示确认中并重新读取订单；取消只提示未完成。H5不发起微信支付；已关闭/已付款移除支付按钮。页面销毁丢弃请求，HTTP层检查当前session/context，幂等意图只留内存。O10线下确认、O11后续主动查单/关单等仍属于X06/P02，画板标PARTIAL。

运行配置：`vi.payment.public-origin` 必须是可信HTTPS源；测试额外配置 `vi.payment.test-endpoint`。还需X01私有版本化根密钥与已发布公司支付/商户/小程序配置。回调消费尚属P02，不将P01当成可独立上线收款闭环。

官方依据：[微信支付 Java SDK](https://github.com/wechatpay-apiv3/wechatpay-java)、[小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)。仅本机协议替身通过，不声称真实商户或微信真机通过。
