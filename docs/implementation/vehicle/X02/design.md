# X02 支付方式与微信商户管理

支付配置的权威归属是收款公司部门，同公司站点共用；取值来自订单receiver_dept_id、原policy_revision_id与后台发布指针。测试/生产环境隔离，不能根据客户端部门、主部门或创建人推定归属。管理复用X01统一Service的部门读写权限、会话代际、最近认证、版本CAS、审计和outbox；配置写入不新增用户/角色授权，不改变auth_version。

后台实际页面覆盖支付策略、微信商户与依赖的小程序凭据。线下/微信独立开关；只保存草稿不改变activeRevision；本地校验成功后显式发布。双关闭须确认，暂停新付费预约。开启微信需已发布且同公司/环境的小程序和商户、mchid、商户序列号/私钥、32字节APIv3密钥、验签材料及AppID绑定确认。可选商户证书核对私钥。回调由可信部署域名生成；密钥只写，保存/切换/离开清空，无浏览器持久化。

线下意图接口只锁定支付方式和原发布版本，不记实收、不释放额度、不延长付款截止。车主只能访问本人订单，在目录锁下复核会话及安全代际，再锁订单/支付单；方式CAS、幂等回执、成功审计与outbox同事务。未知微信结果不能转线下；失败/拒绝另记审计。企业账号仅原订单本人锁定线下且未过期时可读，普通配置GET不回显；后续改配置不替换原收款账号。

历史交易适配器使用原mchid/AppID/商户单号及当前有效同身份签名材料，关闭新微信开关不影响查单、退款查询及通知验签解密。APIv3轮换期间仍尝试同身份已发布且未撤销的历史材料，缓冲在解析完成后擦除；通知校验5分钟时间窗口、签名、原身份和金额。此内部能力不写资金状态；P02完成持久幂等、回调入口/查单/关单状态推进，P03执行退款，X06完成线下凭证核实，不能将本适配器当成完整收款闭环。
