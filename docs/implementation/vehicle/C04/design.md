# C04 实施设计 · 2026-11-01

用户已明确：同公司统一计价、多站点共用；超里程按比例计算后四舍五入到分。

公司以管理员明确选择的公司部门 owner_dept_id 为权威归属，沿用框架部门目录，不根据主部门、部门名称或创建人推断。旗下站点通过 vi_station.dept_id 与部门树匹配；多个公司规则同时命中时拒绝，不能选择最近祖先或最低价格。后台管理规则按 owner_dept_id 和相应功能权限的数据范围校验。

PriceCreate/PriceUpdate 增加公司、TEST/LIVE环境；创建可明确引用已发布/停用版本 sourceRuleId 派生新修订。公司、环境及方案匹配维度一经创建固定；需要更换公司或车型/检测类型则新建方案。运行环境明确隔离：本地/集成为TEST，生产为LIVE，可用部署项vi.pricing.environment显式指定，未知值拒绝。

草稿→提交→独立审核→发布。审核人不得是提交人或该草稿的任一编辑贡献者；贡献者以不可删除的业务审计为准。审核中的内容不可修改；通过后配置冻结，发布校验内容SHA-256与审核绑定；拒绝回草稿并清除审核状态。已发布/停用记录只可派生新修订，不覆盖历史配置。

发布通常拒绝同公司（或部门树中互相关联的公司）、同环境、车型、检测类型的有效时段重叠。若立即替换旧版本，发布请求须明确给出replacesRuleId和原版本；服务端检查两条记录的实际归属、环境、方案条件与版本，并在同一事务停用旧版本、发布新版本。未来生效版本不得立即停掉当前价格造成空窗；可采用不重叠时段排期。停用只影响新报价，不改已建单金额或报价快照。

新增草稿版本试算、按站点匹配已发布规则试算、停用三个接口。两种试算共用同一计算器及真实规则持久化；均不建单、不占容量、不发支付。正式报价通过PricingService按可信站点、车型/检测类型、时间及部署环境取唯一已审核发布版本。旧的仅按车型计数入口改为fail-closed，不能绕过公司和环境约束。

金额全程整数分；距离输入是单程米。ROUND_TRIP先将单程距离乘2，再扣包含里程。CEIL_UNIT按整单位向上进位；EXACT_PRORATA使用精确整数比例，仅在超里程费用结算至分时HALF_UP一次。检测费、起步费加整数分超里程费得到总额。溢出或超过JS安全整数范围拒绝，不用浮点或静默0元。等待费尚未通过P02评审，首期拒绝启用和非零等待参数。

数据库前向增列：owner_dept_id、environment、created_by、config_hash、approved_hash、published_at、source_rule_id；为旧记录允许NULL，但运行时不使用缺归属/审核哈希的旧记录。迁移不猜测回填、不删除记录，输出异常清单。同步增量SQL、完整初始化及资料包DDL、主数据模型和派生物；在专属测试库及新建临时库验证迁移和初装结构一致。不变更现有业务库或生产。

全部写操作权限/实际归属检查、CAS、幂等、成功审计与outbox同事务；拒绝审计独立保留。复用目录保护锁与公司行锁，不依赖Redis清缓存。部门/角色授权变化仍由原框架统一授权服务处理，本功能不写sys用户授权关系。
