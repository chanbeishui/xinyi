## 行为与数据归属

订单独立冻结service_company_id、dispatch_policy_version和认证策略快照，与当时真实站点公司/原收款公司校验一致。公司共享游标跨站轮转，距离只过滤，人工选择不推进自动游标。历史无冻结来源不猜回填，保留原订单、支付和责任并转人工。

公司后台明确维护响应秒数、初始/扩圈直线半径、总截止及业务车型→允许准驾类别矩阵，无运营默认值。保存成功影响后续建单；旧预约/已开始批次继续用原认证快照。没有矩阵或不匹配不派单，不把业务车型名称当法定准驾结论。P03提前N分钟和旧计划保持原快照；D03受控影响预览/应用后续。

D02消费真实DISPATCH_REQUESTED，重新核验资金、正式额度、站点运营、售后挂起、冻结公司和完整司机条件。已明确冻结的新单迁站后仍使用旧公司池，原订单部门权限不迁移；legacy无冻结继续严格校验。已批准且资金可解释的REFUND_ONLY保留履约，未解释退款或余额不足不派单。

每订单只有一活动批次，每司机只有一待响应邀约或在手承接。游标、批次、候选和响应使用统一事务锁序，数据库唯一键作硬兜底。点与近期交互须来自同一仍有效的真实DRIVER设备/session/context和当前公司epoch，不跨设备拼接，也不为SYSTEM伪造MINI Actor。资格、行政、处罚、当日听单、位置/精度、接车时段、半径和其它真实责任均实时复查。

一次只邀一人，同批次同司机不重复。初圈无可用人后只扩一次，空候选转人工。批次总截止取原策略开始后秒数与接车时刻较早者，单次截止再与响应秒数及本人听单截止取最早，相等即失效。重放和恢复不延长原截止，旧任务只能释放精确INVITE holder，不能清掉后来承接。

本人列表、详情、接受/拒绝和当前承接均为真实接口。两个真实有效设备接受同一邀约只生成一份承接；永久invite→assignment映射重放回原结果，不重新占用后来任务。ACCEPT把邀约、订单、承接、INVITE→ASSIGNMENT占用、审计和outbox原子提交；REJECT只结束本邀约并继续调度。接受前无精确地址、坐标、电话、收入或持码信息，当前承接由本人真实assignment加载。

后台按原订单dept范围读写，候选再限冻结公司，不能用管理员主部门或客户端scope扩大。策略query/edit各校真实公司范围；人工/撤回还校独立功能、版本、UUID和原因。原因认证加密，不进GET、消息或幂等结果明文。取消批准委托统一生命周期同事务关闭原批次/邀约、精确释放原INVITE，不借取消删除已接车责任。停听单/退出/切身份均不放弃任务。
