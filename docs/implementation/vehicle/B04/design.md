# B04 读取设计与边界

实现九个GET接口：四端列表/详情，以及车主公开时间轴。主契约保持 V6.1-UNCHANGED，当前以V6.4主OpenAPI为准。Controller 位于 xinyi-rongli/order/controller，统一Service执行功能、部门与承接范围检查，禁止用请求中的部门或X-Client-Type增权。

| 端 | 权威可读集合 | 详情敏感字段 |
|---|---|---|
| 车主 | 当前OWNER基础账户的订单 | 自己的客户金额、订单地址快照；手机号仍脱敏 |
| 代驾 | 当前DRIVER档案的真实承接历史；邀约不算承接 | 当前活动承接且未归还/终结时可见地址和脱敏联系人；历史两个地址及联系人均null且不读取密文 |
| 检测 | 实时员工关联、有效员工/角色/部门、功能权限、当前站点授权以及订单原始dept_id的交集 | 不含客户金额、接车地址、车主联系人 |
| 后台 | biz:order:list/query各自对应的真实订单dept_id范围 | 金额另交biz:order:finance范围，地址另交biz:order:address范围；无权限返回null，不能只凭查询权限读取 |

各列表与详情各有DTO白名单。列表不通过完整详情再删字段来实现；司机、检测、后台列表均不返回客户金额和地址。后台客户脱敏联系人是契约公开字段，不提供完整手机号。空部门集合拒绝，只有服务端确认ALL才允许不加部门集合；不以创建人或用户主部门推断归属。查询参数白名单、单值参数、1..100页大小与溢出检查，客户端不能提交内部范围。列表按created_at/id稳定排序；车主startAt包含、endAt不包含，筛选预约接车开始时间。

详情使用订单公开车辆/站点快照，临时车辆ID允许null。客户私有数据来自B03加密快照，不能用当前地址覆盖历史。存量缺快照明确报状态冲突，禁止猜测回填。公开代驾编号是D加driver_profile ID，不暴露sys_user/手机号/证件。没有可公开区域字段时如实返回“服务区域未单独记录”，不从精确地址截取地名冒充区域。

paymentStatus、实付/已退、售后批准金额、退款进展、争议、当前承接、里程从相应权威记录读取。里程只取同订单同承接的SEALED证据组及CONFIRMED交接，各方向最新记录；反向里程差隐藏负值并提示核查，不外发内部说明。无字段支持的公开售后意见返回null，不能将内部reason充当公开意见。B03幂等重放共用当前车主投影。

读事务使用REPEATABLE_READ保持同一请求内的列表/计数/投影一致。详情访问记录ORDER_DETAIL_READ，拒绝/异常独立审计；均不记录地址、电话、证件、Token或原始备注。未引入订单、额度、身份或授权写接口；没有新的auth_version变更来源。既有撤权版本和实时员工授权继续生效。

当前公开时间轴仅登记已实现的ORDER_CREATE；内部审计及未知事件不外发。后续支付/交接/取消任务须逐项注册公开事件及对应安全文案。allowedActions只给已实现的VIEW_DETAIL，并进一步判断该条订单的query部门范围；不提前显示支付、派单、取消、联系、证据或检测录入动作。

## 页面交付范围

小程序三个业务身份复用订单列表/详情，但URL不能选择身份，API路径取当前可信会话。页面隐藏时清空内容、递增请求序号，旧身份异步响应不回填；HTTP层同时检查session/context。车主分页、状态筛选、金额、详情及时间轴；代驾当前/历史投影；检测站点列表和检测资料/结果只读状态。后台独立列表和详情抽屉，专项无权字段不渲染。进入路径包括身份页、建单成功页和后台动态菜单。

原画板还包含后续业务动作和部分主契约尚未提供的查询条件（如检测端手机号搜索、历史代驾过滤、后台多维搜索/导出）。页面映射明确标PARTIAL并列出余项，不把本轮读取实现冒充完整画板交付；B10检测待办/录入尚未实现。O15已展示公开代驾资料，但联系和交接动作未实现。付款/取消/派单/交接/检测录入等沿原任务继续。

## 既有兼容边界

后台安全链在无有效ADMIN身份时仍沿用框架HTTP200+body.code=401（不含任何订单数据）；已认证后的业务拒绝使用真实HTTP状态。B04测试单独验证该旧协议拒绝，未把它算成成功读取。统一认证错误信封属于后续平台适配，不能声称所有未认证后台响应已满足ApiError协议。

只使用隔离库和明确外部微信/地图协议替身；真实支付短信、微信真机、独立复核及发布未执行。
