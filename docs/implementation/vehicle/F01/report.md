# F01 私有文件全生命周期交付

文件现可经过申请上传、传输实际字节、服务端核验、查询状态、短期读取使用。四个 JSON 业务接口与两个私有存储传输接口已接入真实 Controller/Service/MyBatis；二进制协议见主资料 `04_接口/private-transfer.openapi.yaml`。小程序共用文件客户端随本任务交付，售后页面在 S01 使用它。

归属以本人、原申请、原订单或真实站点判断；后台功能权限与部门范围分开校验，员工取绑定/角色/站点交集，司机仅当前未结束承接。每次读写重查数据库会话代际或后台 auth_version，不能依赖 Redis 强退成功。证件申请尚无权威部门归属，当前只开放申请人本人，不以管理员主部门推断权限；后续 Q01 需补齐明确审核归属。

上传授权300秒、单次不可覆盖租约；文件IO在事务外，完成后以版本CAS提交。最大10MiB、2500万像素，仅实际可解码JPEG/PNG；服务端核对大小、类型、SHA-256。读取票据60秒，必须同时携带当前登录及票据，并再次检查父业务与文件完整性。文件键、磁盘路径和租约不输出；审计只记录脱敏事实。独立复核发现的三个问题均已修复，见 review.md。

数据库按顺序执行既有 `migration_20261104_03_payment_reconciliation.sql`，再执行 `sql/migration_20261105_01_private_files.sql`；已在隔离库验证增量与完整初始化22列、索引及约束一致。SQL同步 `sql/ry_20260417.sql` 与资料初始化脚本，新增权限2970700—2970704仅登记、不自动授权。执行前备份vi_file与菜单表并暂停文件写入口；DDL不可重复执行，不猜测回填历史文件。新部署直接使用最新完整初始化。

部署需配置 `VI_PRIVATE_FILE_ROOT` 为独立私有持久卷绝对真实路径，不能位于公开profile目录，也不能用符号链接；留空时拒绝文件入口。使用既有部署签名密钥 `VI_LOOKUP_KEY`，不能提交到Git。多实例需共享受控持久存储。迁移并配置后重启后端；权限分配通过既有授权服务生效，不直接改角色关联或手工清Token。代理保留两个私有传输路径，生产HTTPS及小程序请求/下载合法域名在发布环境配置。POSIX新建目录700、文件600；已有卷的ACL由部署维护，本轮不替代非POSIX权限验收。

实际测试、构建及结构对比证据见本目录JSON/JUnit；30项文件专项通过。未连接云对象存储、生产环境或微信真机，未删除历史文件。保留政策及争议冻结字段保留，不新增文件删除入口。独立复核通过本次实现范围；完整项目、真实供应商与生产门槛继续单列。

测试资源使用classpath专用定制器：最多缓存4个上下文，框架静态异步管理器使用JVM共享真实4线程池并统一关闭；每个上下文的定时任务仍真实注册/取消。该适配只存在test-classes，未替换业务Service、鉴权、审计或数据库。独立生命周期单测验证关闭一个上下文后下一个仍可调度。
