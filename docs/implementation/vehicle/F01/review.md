复核范围：`file/service/FileAuthority.java`、`PrivateFileStorage.java`、`FileTickets.java`、`PrivateFileService.java`，文件请求 DTO、Controller、MyBatis XML，以及启动层专用 ADMIN 文件安全链。检查当前工作树的实际实现，不以目录存在或历史任务通过代替复核。

## 发现及修复复查

1. 已核验对象在私有磁盘中被普通文件替换后，下载原先仅相信 READY 状态与旧 MIME。实现者已补实际读取字节的长度和 SHA-256 比对；损坏对象返回拒绝，不产生下载成功审计。独立回归用例修改本测试生成文件的同长度字节，验证拒绝输出。
2. 私有目录与文件原先依赖操作系统 umask，POSIX 默认配置可能创建 755/644。实现者已把新建私有目录和新建临时对象分别限制为 700/600；独立回归检查实际 POSIX 权限。非 POSIX 平台使用部署账户与目录 ACL，不能据此声称已验证该平台权限。
3. 员工站点资质原先无条件校验订单部门集合，使尚无订单的站点无法维护资质。实现者已按父业务区分：站点资质使用真实站点部门与实时功能/站点授权，订单文件再检查订单部门范围。独立回归验证无订单站点的真实员工上传、完成及撤销授权后的旧票据拒绝。
4. 集成测试发现框架既有认证入口失败仍返回 HTTP 200、body 401。实现者新增只匹配共用文件 ADMIN 入口的认证链，真实返回 HTTP 401；MINI、ADMIN 令牌不能靠客户端请求头跨域使用。原有平台端点约定未被统一改写。

## 权限、事务和生命周期

- 文件上传者按 MINI accountId / ADMIN userId 两个域分别比较，不能数值混比。业务部门来自原订单或真实站点，个人头像与申请证件采用本人边界。
- ADMIN 同时检查功能权限、部门范围和数据库 auth_version；STATION 取有效绑定、原角色、站点授权及业务部门交集；DRIVER 取当前真实未结束承接。本人头像、订单凭证、站点资质没有共用一种宽泛读取条件。
- 先锁目录守卫和会话，再锁父订单、文件。上传声明、实际文件 IO、核验提交分阶段完成；大文件 IO 不持数据库长事务。单上传租约、原子对象落盘、版本 CAS 和 READY 重放共同防止覆盖及重复完成。
- 服务端识别图片格式、尺寸与实际字节，计算 SHA-256；声明 MIME、大小及文件名不能替代核验。最大 10 MiB，非 JPEG/PNG、尺寸异常、大小不符、未上传和符号链接均拒绝。
- 上传票据和读取票据绑定文件、动作、认证域主体及 MINI 会话上下文，且有截止时间。每次读取仍要求有效登录并重新判断业务权限，签名本身不授予业务权限。票据不放入 URL、幂等缓存或审计文本。
- 成功变更/访问审计随事务提交，拒绝审计独立保留；自由文本访问原因不进入包含证件等敏感内容的审计摘要。元数据响应不暴露磁盘路径、租约或存储对象键。
