## 发现、修复和交叉复查

1. **驳回预览阻断已修复。** 原 PC 驳回填写 0 元，但后端预览把该金额作为“批准仅退款”校验，导致仅退款申请不能在页面完成驳回；持车取消驳回也会显示不恰当的返还要求。现预览显式区分 `APPROVE/REJECT`，旧调用缺省为 `APPROVE`；驳回只能填写 0 元，不预留、不新增返还要求。PC 显式传入决定，并校验返回决定，切换决定后清除旧预览。独立测试覆盖仅退款驳回 0 元可预览、显式及缺省批准 0 元继续拒绝、持车取消驳回保留实际保管与承接。
2. **仅退款与未来派单兼容已修复并复查。** 原 P03 把任意退款预留或已退款都作为派单阻断条件，会使已批准“仅退款、不取消”的预约停止履约。现只放行由原订单同笔支付、同申请和同版批准决定、同金额且无需返还的 REFUND_ONLY 记录完整解释的余额；在途状态解释预留，SUCCESS 解释已退，差额仍转人工协调。独立测试实际执行到期任务：合法预留和已成功退款都继续待派单，多 1 分无法解释的余额仍阻断。没有把取消申请通过此条件放行。
3. **同人排除读取已核实手机号。** 已复查手机号摘要通过 Map 承载真实 `byte[]`，避免 MyBatis 把单值数组当多行结果映射。独立测试使用真实 PhoneCrypto HMAC、已核验账号手机号和框架手机号，无员工绑定也拒绝自审；之后改变手机号仍受贡献时冻结关系限制。MINI/ADMIN ID 没有直接数值比较。
4. **精确任务结束与后续事件。** 未接车取消只释放对应订单、holder 类型和 holder ID 的旧占用；实际结束承接后同事务登记永久键 `ASSIGNMENT_ENDED:{assignmentId}`。独立测试核验唯一事件及准确旧承接 ID；已实际归还后司机的新任务保持原占用与未结束状态。已使用的 CONSUMED 容量不回退。
5. **公开说明与私有凭证边界。** 原 S01 留待后续的公开审核说明已接通独立 `public_opinion`；内部意见保留于后台审核历史，车主售后和订单摘要只见公开说明。后台上传 DISPUTE 草稿不会自动对车主公开；只有明确关联到同订单申请或公开补充历史后，原车主才能读取，其他车主仍拒绝。读取继续经过 F01 短期票据和实时权限校验。


6. **预览幂等契约补齐。** 控制器按主契约要求 UUID `Idempotency-Key`，PC 明确生成并发送预览意图键；Service 在实时权限、版本及贡献者校验后，仅冻结键与请求 MAC，缓存申请 ID，不缓存余额或保管快照。同键同体仍重算当前事实，同键异体拒绝。第 43 个 HTTP 回归已实际通过：缺键 400、同键同体重读最新订单版本、同键异体 409、缓存无实时余额/订单版本，且无业务资金写入。

## 权限、金额、事务复核

- 业务归属从原订单 `dept_id` 获取，资金范围从原支付 `receiver_dept_id` 获取；售后功能权限和资金查询/批准权限分别检查。空部门集合 fail-closed。仅有订单查询权限不会得到未覆盖资金余额或退款金额字段，客户端不能指定内部权限、归属、审核人或返还事实。
- 后台代办与补充资料记录真实 ADMIN 主体；补充有独立 `biz:aftersale:note` 权限，创建权限不能代替。原说明与追加历史分开保存。申请人、后台补充者、可信 MINI 同人关系及贡献时冻结人员均不能自审，解绑不能擦除既有贡献。
- 预览只读、不预留、不保存审核决定；正式审核在事务内按目录、后台账号、订单、支付、申请的顺序加锁，重新核对申请版本、订单版本、实时可退额及保管事实。并发只有一个决定、一笔预留和一个稳定退款号。
- 金额使用整数分，可退额扣除已成功退款和已有有效预留。取消批准可为 0，但只要车辆尚未真实归还就保持 WAIT_RETURN 和原司机/履约/额度；仅退款批准必须大于 0，并保留履约、保管和承接。驳回不新增资金事实，本次 APPLIED 取消意图恢复 NONE，驳回事实保留在独立 case/review 和审计中。
- 正金额按原支付方式登记 WECHAT_API 或 MANUAL_OFFLINE，原商户身份不读当前支付开关重选。审核不直接调用渠道；0 元不建退款单。退款号固定关联申请及审核版本，请求幂等重试不能改金额或换号。
- 审核、取消/返还决定、资金预留、稳定退款单、贡献关系、审计、outbox 和幂等结果在同事务提交。真实数据库约束拒绝写入和 outbox 故障均验证整笔回滚；旧 auth_version 即便 Redis 删除失败也不能继续审核。审计不保存内部意见、自由文本证据或票据原文。
