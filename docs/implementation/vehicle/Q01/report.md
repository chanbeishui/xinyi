# Q01 代驾资格草稿与提交

按用户确认实施严格提交门槛：资料完整、真实核验及培训全部通过后，才可提交审核。四个本人资格接口和小程序认证中心已接通真实Service/MyBatis、私有文件与当前会话；首次申请默认不具备DRIVER，员工按同一标准申请。Q01仅完成资格材料与提交边界，Q02/Q03培训、Q04真实核验及Q05独立审批仍需接续开发，测试中的上游可信结果夹具不代表这些任务已完成。

## 当前可用功能

| 行为 | 权威数据与约束 |
|---|---|
| 读取本人资格 | ACTIVE、已核验手机号、当前MINI会话；OWNER/STATION/已生效DRIVER均可，后台Token不能冒充申请人；任何query均400 |
| 建立草稿 | 明确阅读当前公开同意原文并主动接受；版本及原文SHA256一致；无司机档案时创建未归属公司、听单/新承接关闭的档案 |
| 部分保存 | 姓名、完整身份证、身份证正反面、驾驶证主页/副页、准驾车型、初领日、有效起止日或长期标记；省略保留，显式null清除可编辑字段 |
| 四证件 | 本人上传、当前申请、正确ID_CARD/DRIVER_LICENSE用途且READY，四文件各异；通过既有F01实际传输与校验，提交后禁止再写 |
| 驳回补正 | 只接受可信reject_fields列明项目，保存后仍REJECTED；历史缺结构化范围只读并要求管理员核实，不默认为全部可改 |
| 严格提交 | 完整有效材料、A04显式分配的有效公司、档案/申请双版本与当前明确同意，REALNAME/FACE/BACKGROUND/LICENSE/TRAINING五类当前材料可信PASSED全部满足 |
| 待审核 | 只转SUBMITTED并冻结公司/材料/证件/核验/同意/原因的不可变提交快照，不批准、不开DRIVER、不开放接单 |
| 复审 | 新application明确关联前版，APPROVED/EXPIRED/SUSPENDED历史可开新草稿；保留当前生效资格、证照、复审日期、资格版本、听单、行政开关和既有车辆责任 |

小程序用一个真实认证中心承接D02、D03、D05及D28相关状态；已审核资格与本次申请分开展示。前端提交只按服务端allowedActions开放，服务器仍重新校验。网络/5xx未知结果冻结原body和UUID重试，409保留输入并要求刷新，不把新key或客户端新版本当作覆盖手段。403、身份切换及离页清除敏感输入和旧在途响应；身份证、私有文件票和姓名不进本地持久化。

输入校验包括完整18位身份证格式/校验位、日期与有效期关系；格式校验不等于真实实名核验。身份证GET只返回掩码和是否已提供，空输入省略保留原值，掩码不能回写。长期有效需显式validTo:null；仅允许补正longTermValid而不允许改validTo时，界面禁止顺带清除未被驳回的截止日。

## 同意配置、权限与事务

同意正文没有伪造默认值。运营需通过已有C01同时维护vi.biz.qualification.consent.version和vi.biz.qualification.consent.text；缺任一项时公开配置显示未发布，create/submit按现有统一错误码VI_CAPABILITY_NOT_CONFIGURED拒绝。公开配置同一次SQL取得版本/正文并返回qualificationConsentHash。create和重同意PUT必须提交version、consentTextHash和acceptedConsent=true三件组；同版本修改原文也必须重新阅读勾选。两配置行按固定key顺序锁定到写事务提交，C01写入也排序，防止并发混合版本/正文。

本人材料以真实账号、司机档案和当前applicationId为边界，客户端不能提交公司、账号、资格、核验结果、proofId或内部dataScope。公司延续用户确认的同公司代驾池，只能经A04明确授权认领，不从员工任职、主部门、创建人或历史订单推断。初始NULL归属允许保存草稿，提交必须已有有效公司；profileVersion在提交时再次比较。后台证件查看和审批权限由Q05补齐，本任务不通过普通管理员绕过F01读取原件。

统一目录守卫、账号/会话、档案、申请和有序文件锁，CAS、UUID幂等、成功审计/outbox及冻结快照在同一事务。幂等仅保存目标ID，返回时重读真实授权和当前数据；未知请求不能漂移到新复审。权限撤销与业务写入按现有目录守卫串行，旧Token不能借已读版本继续写；Redis失败不恢复权限。失败或越权按统一审计执行，数据库/outbox/密钥异常整体回滚。

敏感材料AES-GCM封装，AAD绑定账号/申请；材料摘要为带密钥HMAC指纹，避免低熵身份证裸SHA被枚举。实际材料变化才增加material_revision/hash，旧证明不能复用；重同意不使材料版本无故变化。提交原因单独加密并绑定账号/申请/提交轮次，审计摘要、outbox、幂等结果均无原文或证件密文。公开同意正文已公开，SHA256仅用于绑定用户阅读内容。

## 上游证明与后续边界

提交只消费当前申请、当前material_revision/HMAC、已verified_at且非未来、来源非空的服务端证明。五类检查全部PASSED后才有提交action；生产拒绝SIMULATOR/TEST来源。Q01没有客户端或普通配置写proof的接口。TRAINING是Q03未来正式课程/学习/考试汇总结论，必修课程集合和版本由Q02/Q03定义，本任务不猜“学一门”或“全部已发布课程”。后续Q03/Q04写证明须沿父申请事务、版本和材料摘要检查接入，不能凭客户端PASSED晋级。

Q01的正向提交测试直接准备明确的上游可信记录夹具，用于验证消费契约和事务，未调用真实实名、活体、背景、驾驶证供应商或真实学习/考试。Q05尚未实现，实际管理员批准、独立审核、自审隔离、到期/暂停资格与身份生效不能由本任务的既有状态夹具代替。TC-R62-003中的真实接单接口拒绝待D01/D02，TC-R62-005的真实后台批准待Q05，两者保持PARTIAL；D03的真实识别/兼容、D05-passed及D28的完整审核/核验流程画板保持PARTIAL。canAcceptOrder始终false，D01/D02最终准入与实际接单仍待开发；已有在手任务和车辆保管不随新申请失效。
