## 已核对的设计与边界

本人申请不要求先具备 DRIVER，OWNER 与 STATION 均按 ACTIVE、已核验手机号和真实 MINI 会话校验。资格能力从正式 DRIVER 专属提示中移出；员工没有免审通道。后台 JWT、客户端角色或申请字段不授予资格。

申请材料与生效司机资格分开。新申请建立未归属、禁新档案；公司只能经 A04 的明确授权动作认领。PUT/submit 绑定 applicationId 和当前版本，旧本人申请不能漂移到新复审，他人或不存在目标隐藏。复审建立新 application，不覆盖已生效资格、证照、复审截止、资格版本、本人听单或行政开关；EXPIRED/SUSPENDED 的历史非活动申请仍可显式新建复审，但不恢复资格或在手任务。

草稿允许部分保存，未提供字段保留，身份证只返回掩码及是否提供标志，掩码不能当新证号写入。身份和证件材料使用绑定账号/申请的版本化加密封装；材料摘要使用有密钥指纹，不采用低熵身份证裸 SHA。材料实际改变才递增 revision/hash，使旧核验依据失效；同意更新不擅自改变材料版本。

四证件槽位须是本人、当前申请、READY、用途对应且 ID 各异的私有文件。测试实际经过 F01 创建票据、传输 PNG、服务端校验到 READY 后再引用。跨账户、同账户旧申请、未完成、错误用途或重复槽位不能部分写入。提交后禁止继续签发上传、raw PUT 或 complete，已 READY 本人读取不因此撤销；历史提交快照与文件关联保留。

用户明确确认严格提交：资料完整、有效公司与 expectedProfileVersion、当前明确同意，以及 REALNAME/FACE/BACKGROUND/LICENSE/TRAINING 五类当前申请与当前材料 revision/HMAC 对应的服务端 PASSED 汇总、可信且非未来核验时间，全部满足才 SUBMITTED。Q01 不提供写 proof 的客户端或普通配置通路。TRAINING 消费 Q03 正式汇总；必修课程集合、版本、学习墙钟和阅卷由 Q02/Q03 负责，本任务不猜“至少一门”或“全部已发布课程”。测试正向的五类服务端记录是明确的上游边界夹具，不代表真实学习或供应商核验已验收。

同意采用配置中的版本与原文，公开响应返回原文 SHA-256；create 必须明确 acceptedConsent 并提交看到的 consentTextHash。重同意 PUT 的版本/hash/true 三件同组，原文变化即使版本号不变也不得默默接受。公开内容同源一次读取；创建、重同意和提交按固定 key 顺序锁定两配置行至事务提交，C01 写入同样排序。并发发布测试用真实数据库事务分别在 create 与 submit 排队，防止冻结混合内容。

驳回只按可信结构化 reject_fields 补正，补正仍保持 REJECTED，不能先转 DRAFT 再越过字段范围。历史无结构化字段的驳回不猜测为全部可编辑；公开意见与内部 review_opinion 分离。活动申请有永久数据库唯一约束，不静默修复历史多活动记录。

提交冻结公司、档案版本、材料、证件、核验依据、同意及加密原因至独立不可变快照。目录/账号/会话、档案、申请、文件和同意锁序、CAS、UUID 幂等、成功审计及 outbox 在事务内；幂等仅缓存目标 ID，实际响应重读授权。数据库、事件或密钥故障不能留下部分成功。原因、身份证及材料原文不进入审计摘要、outbox 或幂等结果，错误 AAD 不可解密。
