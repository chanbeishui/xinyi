# S01 售后申请与进度交付

车主可从订单进入取消并退款或仅退款申请，填写原因、精确到分的金额及最多9张私有凭证，查看本人售后列表、进度和原申请，追加说明与凭证。草稿按环境/账号/订单隔离；提交结果未知时保留原幂等请求并先刷新核实；同单重复入口返回原申请，不覆盖原原因。上传与预览使用F01实际私有文件接口。

申请与查询按原订单owner_account_id授权，客户端不能指定部门、申请人或审核/资金状态。事务按目录、会话、订单、支付、申请、凭证顺序加锁；凭证必须READY、同单、本人上传且用途DISPUTE，任一越权整笔拒绝。实际收款确认后才能申请，可申请金额扣除已退款和已预留金额。成功审计、outbox、幂等与写入同事务，拒绝保留独立审计，不把原原因和附件明文放进事件载荷。

已支付但未接车仍进入人工审核。取消并退款只设置APPLIED以阻止新派单；仅退款保留履约、保管和司机占用。申请不占退款预留、不发起退款、不伪造还车。批准金额未确定返回null，原说明不可修改，补充资料只追加并校验申请版本。内部审核意见不直接公开，publicOpinion暂为空；S02需要单独公开结论字段并接通，退款执行仍待P04。

数据库先执行 `sql/migration_20261105_01_private_files.sql`，再执行 `sql/migration_20261105_02_aftersale_notes.sql`；后者新增原因代码与追加资料表，同步完整初始化。两张售后表增量升级与完整初始化一致，见schema-verification.json。执行前备份原申请并暂停售后写入口，DDL不可重复；历史原因和凭证不修改、不猜测补充记录。执行后重启后端，不需手工清理缓存。
