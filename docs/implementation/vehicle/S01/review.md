## 规则与权限复核

- 接口只接受真实 MINI OWNER 主体；原订单是申请、详情、列表及补充资料的权威归属。请求不能指定部门、申请人、资金或审核状态。列表 SQL 按原订单车主过滤，详情和写操作加载数据库原订单再次检查，猜测申请 ID 不能越权。
- 按目录、会话、原订单、支付、申请、文件次序加锁。支付实际收款已确认才可申请；可退余额扣除已退款与已预留金额，金额使用非负整数分，不进行浮点计算。申请不增加退款预留，也不修改支付成功状态。
- `CANCEL_REFUND` 仅登记 APPLIED 取消意图，阻止新派单；不伪造实际还车，不释放司机占用或额度。`REFUND_ONLY` 不改取消、保管及履约事实。已支付但未接车仍进入人工审核，申请不直接进入退款中。
- 同订单有效申请优先返回原记录，保留原理由与附件；请求幂等与数据库 active_order 唯一键共同防止重复。原订单版本控制新申请，申请版本控制追加资料；并发同版本补充只有一次成功。
- 原申请不可覆盖，补充说明和凭证进入追加表。凭证整组按稳定 ID 次序核验，必须为 READY、原订单、本人上传的 DISPUTE 文件；任一不符整体回滚。
- 申请/补充、取消意图、成功审计、outbox 与幂等结果同事务；失败保留独立拒绝审计。审计及 outbox 不放入原理由或附件明文；幂等只缓存申请 ID，读取结果时重新检查当前权限。
- 待审核批准金额返回 null，不能伪装为批准 0 元。公开投影只给业务进度和原申请/追加资料，不输出申请人内部字段、原始支付信息或内部审核意见。
