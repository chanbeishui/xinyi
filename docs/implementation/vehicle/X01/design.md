# X01 实现边界与运行方式

本轮实现12个管理接口与供后续支付、短信、订阅适配器调用的配置读取基础。任务切片没有画板；管理页面、实际供应商检测/发送、预支付和历史支付维护分别由P01、X02–X07实现。本轮没有真实支付、短信发送或生产变更。

权威归属为vi_integration_profile.owner_dept_id；公司和TEST/LIVE环境创建后不可变。所有Service检查ADMIN主体、对应功能权限、该权限的多部门范围和有效部门；空集合拒绝。创建明确选择公司部门，不使用操作者主部门。PAYMENT_POLICY、WECHAT_APP按公司/环境唯一DEFAULT配置，短信和商户可建立多个显式引用的配置。依赖仅允许同公司、同环境、正确类型的当前发布版本。

写事务按目录授权守卫→用户真实auth_version→配置父记录加锁，校验CAS；草稿、校验、发布历史均追加。幂等仅存请求HMAC和脱敏结果；成功审计、outbox与指针推进同事务，失败审计独立记录。发布/回滚要求15分钟内真实后台登录，Token续期不更新时间；旧会话无authenticatedAt需重新登录。查询不改变授权，不递增用户auth_version。

相同配置和秘密引用可复用已有不可变revision，但保存仍递增父version。新增check.target_version绑定检查时父版本，避免同内容保存后复用旧check。检查有效期15分钟，发布必须满足目标revision、contentHash、check PASS、版本及有效期，并在锁内重验当前依赖与秘密。回滚仅限曾发布的版本，重新校验，不恢复撤销或过期秘密。草稿保存不改变active_revision_id；新操作仅从主库读取有效发布指针，不依赖Redis缓存。依赖版本更新后，父配置须同步引用新版本并重新检查发布。

LOCAL检查字段、依赖、RSA/证书格式、秘密可解密性等，不代表供应商验证。READ_ONLY、LIVE_EVIDENCE尚未安装对应供应商能力时返回PARTIAL（配置无效则FAIL），realPaymentVerified始终false；不能凭此发布。微信支付配置需完整商户/AppID关联、APIv3密钥、签名及验签材料；两个支付开关独立，双关闭首次发布需acknowledgeNoPaymentMethods=true，不能当成免费订单。B03现有支付门禁已接入实际解密，银行账户或微信密钥不可用时不能假定其可用。

秘密使用AES-256-GCM、随机nonce、绑定公司/环境/配置/槽位的AAD，数据库仅存密文、密钥版本和不可逆HMAC指纹。GET只返回配置状态，运行时回调使用后清零秘密字节数组。KEEP/省略保留，REPLACE拒绝空值和掩码；CLEAR只可撤销未发布草稿秘密，曾发布秘密保留用于历史维护，通过替换轮换。撤销历史秘密后回滚会失败。不存在明文降级或通用接口读取秘密原文。

主密钥从部署方私有配置注入`vi.integration.keys.current-version`和`vi.integration.keys.versions.<版本>`（Base64编码的32字节随机密钥），仓库不提供默认值或真实密钥。部署方保管和备份根密钥；轮换先增加新版本，再切换current-version，并保留旧版本以读取历史密文。丢失旧版本将返回503，需要恢复原密钥；不能用空值或新密钥替代。该实现为部署注入的版本化主密钥，不宣称已经接入外部云KMS。凭据维护要求TLS或本机回环连接；代理须在可信边界终止TLS，不能信任任意客户端转发头。

PHONE测试白名单的手机号加密并仅返回掩码；MINI_ACCOUNT必须属于所引用的同公司已发布小程序，返回账号ID而非OpenID。撤销带CAS及操作者原因审计。白名单记录不自行触发真实发送。

本轮同时修复两项接口兼容问题：公开响应将内部JsonNode转换为普通Map/List；业务错误详情尊重字段白名单。`/api/admin/**`未认证返回真实401、no-store和标准ApiError对象，旧平台/system接口不改。B04先前记录的后台认证信封债务在本轮解决，旧证据保持原样。
