已接通建单计划快照、可信支付同事务登记、到点待派单、数据库租约领取和异常补偿。本次变更按仓库要求展开Java/SQL排版并补充关键中文边界注释。未来预约保持SCHEDULED；到点且资金、双额度、站点和取消/承接状态有效时进入PENDING_DISPATCH，唯一登记DISPATCH_REQUESTED。过计划点付款同步评估原报价最短提前量；过期或运营条件不满足转人工协调，保留资金和额度。司机候选、邀约轮转及受控重排仍属D02，本任务不冒充已完成司机派单。

## 配置与运行

C01现有后台配置维护`vi.biz.dispatch.lead.minutes`（0—10080整数），按版本CAS保存。建单冻结`dispatch_at`与`dispatch_config_version`；修改N只影响新订单。缺失配置拒绝新建单，不把30分钟测试值设为生产默认值。

复用`vi_outbox`的绝对到期时间、短租约、版本CAS、退避及永久事件键。扫描定向领取ORDER_DISPATCH_DUE，未实现消费者的旧事件不会堵住此类型。旧订单没有原计划快照时唯一登记DISPATCH_PLAN_MISSING；任务计划版本不一致登记DISPATCH_PLAN_CONFLICT，不猜测回填。取消审核或有效承接阻止再次派单，后续恢复须经过受控重排。

自动扫描及该类型的通用中继消费默认关闭。启用前先完成运营参数和发布检查，设置`VI_DISPATCH_JOBS_ENABLED=true`后重启；周期由`VI_DISPATCH_JOBS_DELAY_MS`控制，默认5000毫秒。已过点的可信付款始终同步评估，关闭扫描不撤销已登记的订单或资金事实。D02尚未接入时DISPATCH_REQUESTED保留待处理，不能宣称已通知司机。
