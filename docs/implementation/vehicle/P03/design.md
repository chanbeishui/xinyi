# P03实现范围与边界

来源：主PRD3.3、I11、IT06及任务包P03。基线1038ab1；P02/C03/E06均已VERIFIED。P03提供计划时间快照、可靠到期任务和待派单事件；D02负责司机资格、轮转、邀约及扩圈，TC-054的既有计划预览/批准重排仍归D02后续。本任务不提前占用司机，不实现自动退款。

## 权威归属与事务

任务只保存原订单ID与计划版本，站点/部门/资金/取消/承接状态均重新从数据库加载；不提供客户端定时任务写入口。沿用目录守卫→订单→支付锁顺序；领取outbox租约的短事务先结束，再进入业务事务，避免持任务锁反向锁订单。订单推进、永久源事件、审计与outbox同事务，失败全部回滚。角色、任职及auth_version不变，旧会话失效机制沿用既有支付/建单验证。

后台C01现有配置接口维护全局参数`vi.biz.dispatch.lead.minutes`，按配置版本CAS保存并审计，只接受0—10080的整数。范围上限为技术输入边界，未设置生产默认值；缺失时阻止新建单，不能把测试30分钟当运营决定。所有公司使用此全局派单提前量；计价与收款仍按已确认的公司归属。建单在配置锁内冻结dispatch_at=pickup_starts_at−N分钟及dispatch_config_version，参数修改不追改旧单。

## 到期及补偿

付款成功在原事务登记`DISPATCH_TIMER:{orderId}`，next_attempt_at为原计划绝对UTC时点。已过计划点时在支付事务内立即评估，必须满足原报价policy.lead最短提前量。未来任务由可注入UTC Clock扫描；E06短租约、版本CAS、退避和永久event_key保证任务重试与恢复。定向领取ORDER_DISPATCH_DUE，未接入消费者的历史通知不能堵住此队列。

推进前复核SUCCESS实付足额、无退款预留/已退、两类同站正式额度、站点及权威部门有效、未取消且无承接。到期有效订单进入PENDING_DISPATCH并唯一登记DISPATCH_REQUESTED；时段已开始、资金/站点/额度异常进入MANUAL_DISPATCH并登记DISPATCH_REVIEW_REQUIRED，保留原资金及额度等待协调，不自动退款或重卖额度。取消审核或已有承接只登记阻断，不复活订单。

缺失timer从原订单快照补登记。旧订单没有计划时间/版本时登记DISPATCH_PLAN_MISSING，不用当前配置补值；任务计划版本不符登记DISPATCH_PLAN_CONFLICT。被取消、旧版本或其他流程阻断后的恢复必须由后续受控重排流程明确决定；不自动清除既有事件重新派发。

## 运维与数据

复用已有vi_order.dispatch_at/dispatch_config_version及vi_outbox，不增加表、列、索引或基础权限数据，本次无需迁移SQL。部署先在C01配置派单提前分钟，核对旧订单缺失计划和异常任务，再按发布门槛启用VI_DISPATCH_JOBS_ENABLED=true并重启。默认仅持久化计划，后台扫描及通用中继对此类型的消费均关闭；已过计划点的可信付款仍同步校验并登记待派单/协调状态。VI_DISPATCH_JOBS_DELAY_MS默认5000，生产多实例需UTC时钟同步。

未实现D02时DISPATCH_REQUESTED事件保留READY，不能据此声称已给司机发出邀约。FAILED任务需先核对失败原因再受控恢复；租约过期自动重领，业务幂等仍由订单状态及永久源事件约束。未开发的邀约超时/24小时确认等由各自业务任务定义，不借本任务默认改写。
