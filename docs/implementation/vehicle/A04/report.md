## 权限、隐私与事务

公司采用既有计价/支付约定：后台明确选定有效sys_dept承担业务公司，不以部门名称、树层级、员工绑定、用户主部门或历史订单推断。现有框架没有独立公司类型字段，正确公司/站点组织树由管理员维护；字段有效不代表自动识别法律主体。

六业务接口只接受真实ADMIN和对应功能、公司数据范围；无登录/MINI/伪造realm为真实HTTP401。空范围fail-closed。后台查询和写入使用独立权限，归属迁移另需biz:driver:assigncompany并覆盖原新范围；恢复与暂停也分别授权。公司选择器复用真实GET /system/dept/list，另需system:dept:list；框架HTTP200中的非成功code必须拒绝，不能当目录成功或通过新接口旁路。

权威目录守卫、实时后台auth_version与公司范围、司机行锁、CAS、幂等、成功审计及outbox在同事务；目录守卫与统一授权事务串行，撤权后排队的旧请求拒绝。Redis删除故障不能恢复旧Token。重复UUID同体只执行一次，异体409；审计/outbox或数据库失败整体回滚。

操作原因和备注前后值以AES-GCM加密审计，AAD绑定ADMIN、动作和真实司机ID；审计摘要只含受控公司/开关及加密封装，GET不回原因，outbox及幂等结果无明文。未核验旧phone_cipher不展示phoneMask；没有司机历史权限则不伪造归还数0。历史计数、当前assignmentId及holderId按原订单范围掩码，ID不可见时真实occupied仍为true。

## 新承接与后续功能的边界

DriverNewAssignmentPolicy只实现本任务基础资格检查。行政开关、本人听单意愿、资格和真实占用分开；A04不伪造客户端可达、定位新鲜度、处罚轮次及车辆兼容判定，availableForNewOrder保持false，基础条件通过后明确DISPATCH_ELIGIBILITY_NOT_READY。D01/D02后续派单/接受必须实时复用并扩展统一判定，未接受邀约的处理也不能绕过暂停状态；本任务没有模拟“接受邀约”API冒充完成。

不创建/审批驾驶资格，不开放证件原图，不通过备注更改身份。Q01/Q05、真实H/D交接和费用对账自审仍由后续任务验收。D27/S15已接通本人工作/真实身份与现有服务入口；资格、听单、本人对账及付款摘要未接通部分按钮明确不可用，画板保持PARTIAL，不显示虚构收入/0余额或空账单。B28实际管理行为已验证，费用入口未开发部分单列。
