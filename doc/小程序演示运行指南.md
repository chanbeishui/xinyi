## 二、必须先拿到的两项授权

### 1. 微信开发者权限（决定你能不能用这个 AppID 打开工程）

AppID 属于某个小程序账号，**只有该账号的管理员能给你授权**：

1. 管理员登录 [微信公众平台](https://mp.weixin.qq.com) → 左侧「管理」→「成员管理」→「项目成员」。
2. 在「开发者」一栏点「添加成员」，填入**你本人的微信号**（需对方搜索到你的微信号或手机号）。
3. 你在微信里收到邀请后确认，即成为开发者，可在开发者工具中打开该 AppID 的工程。
4. 只做体验（不调试代码）时，加在「体验成员」即可，但**体验成员无法用开发者工具打开工程**。

> 判定标准：开发者工具导入项目时，右上角显示 AppID `wx22f41349e671b362` 且不报「该小程序未授权 / 无权限」。若报错，说明你的微信号不在成员列表里。

### 2. 开发者工具登录与服务端口

- 打开微信开发者工具 → 用**已获授权的微信号**扫码登录（当前机器尚未登录，CLI 直接打开会报 `code 10 需要重新登录`）。
- 若要脚本化打开项目，需在「设置 → 安全设置」中开启 **服务端口**；不开启也能手动导入，不影响演示。

### 3. AppSecret 与真实微信登录（演示阶段不需要，且当前不可用）

- 演示走**联调登录**：后端 `rongli.wechat.mock=true`，把登录 code 当 openId 用，不校验 AppSecret。
- 后端 `AuthService.resolveOpenId()` 未实现真实 `jscode2session`，把 mock 关掉会直接返回 **503 微信登录通道未配置**。因此演示阶段**不要**去改 `rongli.wechat.mock`，也**不要**把后端 `rongli.wechat.appId` 改成真实 AppID（会造成与已播种账号的 `app_id` 不一致，登录后是新账号、无数据）。

## 三、启动步骤（电脑端演示，最常用）

```bash
# 0) 首次运行：从示例文件生成本地环境配置（.env 含本地联调标识，不入库）
cd /e/codex/xinyi/xinyi-rongli-wx
cp .env.example .env            # Windows: copy .env.example .env

# 1) 后端（若已在运行可跳过；本机 shell 有端口注入，必须显式指定 8080）
cd /e/codex/xinyi
java -jar xinyi-admin/target/xinyi-admin.jar --server.port=8080

# 2) 小程序开发版（watch 模式，改代码自动重编译）
cd /e/codex/xinyi/xinyi-rongli-wx
npm run dev:mp-weixin          # 产物：dist/dev/mp-weixin
# 只想出一次性产物：npm run build:mp-weixin   # 产物：dist/build/mp-weixin
```

3. 打开微信开发者工具 →「导入项目」→ 目录选 `E:\codex\xinyi\xinyi-rongli-wx\dist\dev\mp-weixin` → AppID 会自动读取为 `wx22f41349e671b362`。
4. 进入后点右上角「详情 → 本地设置」，勾选：
   - ☑ **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**
   - ☑ 将 JS 编译成 ES5（部分老机型需要）
5. 模拟器会自动进入登录页。

> 注意：**导入的目录必须是编译产物 `dist/dev/mp-weixin`，不是 `src`**。`src` 是源码，开发者工具无法直接运行。

用命令行打开（需已登录 + 已开服务端口）：

```bash
"/c/Program Files (x86)/Tencent/微信web开发者工具/cli.bat" open \
  --project "E:\codex\xinyi\xinyi-rongli-wx\dist\dev\mp-weixin"
```

## 四、登录与账号切换

登录页有「联调登录标识」输入框（由 `.env` 的 `VITE_LOGIN_MODE=mock` 控制显示），填不同标识即换身份：

| 登录标识 | 身份 | 可见视角 |
| --- | --- | --- |
| `dev_owner_001` | 演示车主 | 车主（预约、车辆、订单、售后） |
| `dev_driver_001` | 演示代驾·陈师傅 | 车主 + 代驾（接单、留证、交接、对账、培训、处罚） |

- 后端管理端：`http://localhost:80`（或前端 dev server）→ `admin / admin123`，用于配合演示派单、审单、看板。

## 五、真机预览与调试

手机无法访问电脑的 `localhost`，必须先解决接口地址：

1. 确认手机与电脑连**同一个 Wi-Fi**（本机 `192.168.16.88`）。
2. 改 `E:\codex\xinyi\xinyi-rongli-wx\.env`（从 `.env.example` 复制而来）：
   ```ini
   VITE_API_BASE=http://192.168.16.88:8080
   ```
3. 重新编译：`npm run dev:mp-weixin`（或在跑着的 watch 里改完会自动重编译）。
4. 验证手机可直连：手机浏览器打开 `http://192.168.16.88:8080/api/common/stations`，能看到 JSON 即通；打不开多半是 Windows 防火墙拦了 8080 入站，需放行（专用/公用网络都勾上）或临时关闭防火墙。
5. 开发者工具点「**预览**」→ 手机微信扫码 → 打开的是**开发版**；扫码后若接口全红，按下法处理：
   - 预览页面右上角「···」→ 打开「开发调试」，此时「不校验合法域名」才生效；
   - 或改用「**真机调试**」：工具点「真机调试」→ 扫码 → 电脑上出现远程调试面板，可看 console/network，不受域名校验限制（受同一开关控制）。
6. 体验版（可选，给非开发同事试用）：工具「上传」→ 公众平台「版本管理」→ 设为体验版 → 添加体验成员。**体验版要求接口域名是已备案的 HTTPS 域名**，本地 `http://192.168.x.x` 不可用，因此本地演示请用「预览 / 真机调试」两条路径。

## 六、推荐演示动线（约 8 分钟）

1. **车主端**：登录 `dev_owner_001` → 添加车辆（车型选 `sedan/suv/mpv/pickup/van`，选错会在报价时报「车型不在可选范围内」）→ 选上门时段 → 报价（示例 330 元）→ 提交订单 → 支付（MOCK 通道，直接成功）。
2. **后台**：`admin/admin123` 登录 → 荣利业务 →「派单管理」→ 找到订单点「立即派单」（跳过接车前 30 分钟等待）。
3. **司机端**：登录 `dev_driver_001` → 接单 → 出发 / 到达 → 车主侧出示 4 位交接码 → 拍照六类留证（车头/车尾/左侧/右侧/仪表盘/内饰）+ 里程 → 交接完成。
4. **检测点**：登录 `dev_station_001` → 收车 → 行驶证核对（可拍正副页）→ 登记检测结果（PASS）→ 交车。
5. **司机**：取车 → 归还车主（车主核验）→ 提交售后（可选）→ 车主确认服务完成。
6. **后台**：运营工作台看指标、订单时间线（21 个节点）、司机对账台账。

演示前若想让订单立刻可派单，注意派单时点是「接车开始时间 − 提前量（默认 30 分钟）」，把预约时段选在**当前时间之后 30 分钟以上**即可。

## 七、常见问题（按出现频率排序）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 导入项目提示「无权限 / 该小程序未授权」 | 你的微信号不是该项目成员 | 让管理员在公众平台「成员管理」加你为开发者，重新扫码登录 |
| CLI 打开报 `错误 需要重新登录 (code 10)` | 开发者工具未登录 | 手动打开工具扫码登录；需要 CLI 自动化再到「设置→安全设置」开服务端口 |
| 所有接口 `request:fail url not in domain list` | 未勾选不校验域名 / 真机未开调试 | 详情→本地设置勾选「不校验合法域名」；预览页右上角开启「开发调试」 |
| 真机接口全部超时，模拟器正常 | `.env` 仍是 `localhost`，或防火墙拦 8080 | 改 `VITE_API_BASE=http://192.168.16.88:8080` 重编译；放行入站 8080 |
| 登录后订单/车辆全是空的 | 走了真实 `wx.login` code，每次生成新账号 | 确认 `.env` 为 `VITE_LOGIN_MODE=mock`，在登录页填 `dev_owner_001` |
| 报价报「不在任何检测点服务范围内」 | 上门地址不在检测点覆盖范围 / 车型无检测点支持 | 换检测点覆盖内的地址；车型改用 `sedan` 等字典值 |
| 站点看不到「收车」按钮 | 当前账号未绑定站点或视角仍是车主 | 用 `dev_station_001` 登录，并在「切换视角」选检测点 |
| 「需要获授权检测员工完成站点侧交接」 | 站点是核验方，须由站点发起交接、司机出码 | 在站点订单页发起「司机交车给检测点」，让司机报码 |
| 交接码连错 3 次被锁 | 防爆破锁定 | 换一笔订单演示，或按运维流程清 `vi_handover_attempt_guard` |
| 支付无法调起微信支付 | 支付通道为 MOCK | 演示阶段用 MOCK 直接成功；真实支付需配商户号并接 `WECHAT` 通道 |
| 上传照片失败 | 后端文件目录不可写或接口参数不符 | 检查后端 `uploads` 目录权限；上传走「申请→上传 content→complete」三步，参数为 `{size, sha256}` |
| 模拟器白屏 / 编译报错 | 导入的是 `src` 或构建未完成 | 导入 `dist/dev/mp-weixin`，重新执行 `npm run dev:mp-weixin` 等编译完成 |
| 端口 8080 起不来，报 1095 被占用 | 本机 shell 存在端口环境变量注入 | 启动命令显式加 `--server.port=8080` |
| 打包时 `xinyi-admin.jar` 改名失败 | 旧进程仍占用 jar | 先结束占用 8080 的 java 进程再 `mvn package` |

## 八、演示注意事项

1. **只用于演示**：`rongli.wechat.mock=true`、短信验证码回显 `devCode`、MOCK 支付通道，都必须在正式上线前关闭/替换。
2. **不要把 AppSecret 写进小程序代码**：AppSecret 只能放后端，且当前后端并未实现 `jscode2session`。
3. **演示账号数据是按 `app_id=wxdev000000000000` 播种的**，改后端 `rongli.wechat.appId` 会导致登录后数据为空；确需改，请同步更新 `vi_account.app_id`。
4. **上传的照片落在后端本地磁盘**，换机器演示前确认 `uploads` 目录随库一起迁移，否则历史照片 404。
5. 演示结束记得把 `.env` 的 `VITE_API_BASE` 改回 `http://localhost:8080`，避免下次在模拟器里连不上。
6. 小程序端接口地址与登录模式均通过 `.env` 注入，改完**必须重新编译**（watch 模式会自动重编，但要等编译完成再刷新模拟器）。
