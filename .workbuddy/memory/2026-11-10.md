## 新建检测点必 500：dept_id 从未赋值
- 现象：检测点管理 → 维护检测点 → 保存，`POST /prod-api/api/admin/stations` 返回 500，
  页面 toast「服务暂时不可用，请稍后重试」。
- 根因：`vi_station.dept_id` 是 NOT NULL 且无默认值，`StationMapper.insert` 的 INSERT
  里也写了 `dept_id`，但 `StationAdminService.createStation` 只 set 了 name/address/lng/lat，
  **从来没有 setDeptId** → 插入时 NULL → `Column 'dept_id' cannot be null` → 500。
  `ViExceptionHandler:73` 把未捕获异常统一兜成 500 + 那句 toast，所以看不出真实原因。
- 与地图选点无关：地图是前端组件，不参与保存。
- 修法（commit f472548）：`deptScope.writeDeptId(req.deptId, "...")`
  - 超管：沿用请求值，没传则当前部门；
  - 受限账号：请求值必须在任职范围内，否则 403；没传则主任职部门；
  - 仍为 null 时明确抛「请选择检测点归属部门」，不再落到 500。
  - `DriverDtos.StationUpdateReq` 增加 `deptId`。
- 前端：表单加「归属部门」树选择，**创建可选、编辑只读**（改归属会让历史订单的数据范围漂移）。
  部门树接口 `/system/user/deptTree` 要求 `system:user:list` 权限，检测点管理员常常没有，
  所以取不到时隐藏选择器，由后端按任职部门兜底，不阻塞创建。
- 这次改动含 Java，**必须重发后端 jar**（前几轮只发前端）。

## 地图"加载失败"（未解决，待查）
- 页面地图区域只显示"地图加载失败"，说明 `MapPicker.init()` 的 catch 命中，
  即 `https://webapi.amap.com/maps?...` 脚本 onerror（网络层失败），
  而不是「未配置地图服务」那种提示（那代表 key 为空）。
- 排查方向：F12 → Network 过滤 `amap`，看脚本请求的状态；Console 里高德的错误码
  （`INVALID_USER_KEY` / `INVALID_USER_SCODE` / `USERKEY_PLAT_NOMATCH` / 域名白名单）。
  高德 key 分「Web端(JS API)」与「Web服务」，类型选错也会失败。
- 注意：`sys_config` 的 `rongli.map.key` 改完要在后台保存一次参数，否则读到缓存旧值。
