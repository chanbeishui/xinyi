## 新建检测点必 500：dept_id 从未赋值
- 现象：检测点管理 → 维护检测点 → 保存，`POST /prod-api/api/admin/stations` 返回 500，
  页面 toast「服务暂时不可用，请稍后重试」。
- 根因：`vi_station.dept_id` 是 NOT NULL 且无默认值，`StationMapper.insert` 的 INSERT
  里也写了 `dept_id`，但 `StationAdminService.createStation` 只 set 了 name/address/lng/lat，
  **从来没有 setDeptId** → 插入时 NULL → `Column 'dept_id' cannot be null` → 500。
  `ViExceptionHandler:73` 把未捕获异常统一兜成 500 + 那句 toast，所以看不出真实原因。
- 与地图选点无关：地图是前端组件，不参与保存。
- 修法（commit f472548）：`deptScope.writeDeptId(req.deptId, "...")`
  - 超管：沿用请求值，没传则当前部门；
  - 受限账号：请求值必须在任职范围内，否则 403；没传则主任职部门；
  - 仍为 null 时明确抛「请选择检测点归属部门」，不再落到 500。
  - `DriverDtos.StationUpdateReq` 增加 `deptId`。
- 前端：表单加「归属部门」树选择，**创建可选、编辑只读**（改归属会让历史订单的数据范围漂移）。
  部门树接口 `/system/user/deptTree` 要求 `system:user:list` 权限，检测点管理员常常没有，
  所以取不到时隐藏选择器，由后端按任职部门兜底，不阻塞创建。
- 这次改动含 Java，**必须重发后端 jar**（前几轮只发前端）。

## 检测点页视觉收口（commit 8b92858 / bb13958 / 085357d）
- **操作列按钮换行**：`link` 按钮带 `el-button--primary` 类，`brand.scss` 的
  `.el-button--primary { box-shadow: 0 6px 16px rgba(22,119,255,.22) }` 也会命中，
  link 按钮看起来是一个个浮起的浅蓝胶囊；再叠加 Element 的 `.el-button + .el-button
  { margin-left: 12px }`，三个按钮在 200px 列里必定换行。规范：`.rl-page .el-button.is-link`
  24px 高 / 6px 圆角 / 底色透明 / 间距交给容器 gap（`.rl-ops` flex 容器）。
- **`.rl-hint` 在抽屉里失效**：drawer/dialog 内容被 teleport 到 body，`.rl-page` 后代选择器
  与 `--rl-ink-3` 变量都取不到。`.rl-hint` 是 `RongliPage.vue` 里的**全局**样式（该 style
  没 scoped），所以背景还在，但 `color: var(--rl-ink-3)` 解析失败退化成深色。已改成字面色值。
- **地图被压成细窄一条**：`MapPicker` 根 div 是 `.el-form-item__content`（flex）的子项，
  没宽度约束就按内容收缩；且 `el-drawer` 从 0 展开到 560px 期间已完成 AMap 初始化，
  画布按 0 宽铺瓦片，之后不重绘 → 窄条 + 标记贴左下 + 右侧留白 + POI 文字被裁。
  修法：根 `width:100%;min-width:0`，初始化前 `waitForSize`（rAF 轮询 clientWidth），
  挂 `ResizeObserver` 调 `map.resize()`，创建用单一 Promise 复用防并发建两张图。
- **地址搜索**：`MapPicker` 通过 `defineExpose({ locate })` 暴露；`Geocoder.getLocation`
  解析 "省市区+详细地址"，无结果回退 `PlaceSearch`，8s 超时保护（插件异常时回调不来，
  否则按钮一直 loading）。搜索**不回写输入框**（`onMapAddress` 只在地址为空时回填）。
- 构建验证：`npx vite build --outDir dist-verify-<唯一后缀>`，**每次都要新目录**，
  否则 safe-delete 保护会在 emptyDir 阶段报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（编译其实已通过）。
