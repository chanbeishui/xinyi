## 检测点地址改为省市区下拉（commit ed2e469 / 4587a46 / 8bbfc7e）
- 行政区划数据**不入库也不入仓**：`utils/region.ts` 用高德
  `DistrictSearch({ level:'country', subdistrict:3 })` 一次取全国三级树，压成
  `{省:{市:[区]}}` 存 localStorage `rongli.region.tree.v2`（TTL 30 天）。
  静态表（两三千条）进仓库会很快过期，还得手工维护撤县设区。
- **直辖市补一层同名市**：高德把区县直接挂在省级（或只套一层「市辖区」），
  不补的话市级下拉会出现一堆区名；`onlyOnePlaceholder` 分支处理「市辖区」包装。
- **拆分用「按后缀切词」而不是 startsWith**：`/^(.{2,}?(?:省|自治区|特别行政区))/`
  这类正则先切出 token 再精确比对；startsWith 会把「吉林市」吃成「吉林省」。
- **拼接去重**：`joinAddress` 逐个剥掉 detail 开头与已选行政区重复的前缀。
  简称（去掉省/市/区后缀）只在「后面紧跟另一个已选行政区」时才认，
  否则「海南路1号」会被当成「海南省」；吉林省 vs 吉林市不能合并，
  所以同名合并要求两边都以「市」结尾（直辖市）。
- 编辑旧记录：`splitAddress` 回填三个下拉；老数据不写省（「茂名市茂南区…」）
  时按市级反查归属省；拆不出来整串留在 detail，信息不丢。
- 取不到行政区划（没配 Key）时下拉置灰 + 提示条说明，详细地址仍可手写完整地址，
  不阻塞录入。

## 外部接口额度/权限错误必须直说（commit 237ad95 / 95857b3）
- 用户明确要求：外部 API 出现调用次数限制时，提示语要**直接写给用户看的原因和动作**，
  例如额度用尽必须是「高德地图基础LBS服务每月使用额度已达上限，请技术人员扩容」，
  不能兜成「服务暂时不可用/加载失败」——运营会反复重试，能处理的人却看不到信号。
- 落地：`utils/amap.ts` 的 `amapErrorMessage(result)`，按 `infocode` 查表（兼认只带
  `info` 的回调，`AMAP_ERROR_CODES` 做 info→code 映射）。额度类 10003/10044/10045、
  `DAILY_QUERY_OVER_LIMIT`/`OVER_QUOTA` 统一走 `QUOTA_MESSAGE`；表里没有的新码若语义仍是
  `*_OVER_LIMIT|QUOTA`，按额度提示兜底，其余保留原始 info/infocode 便于排查。
- 串接点：Geocoder/PlaceSearch `status==='error'` → 写状态条并**跳过兜底检索**
  （服务级错误重试只会再错一次）；DistrictSearch 失败把原始原因抛给抽屉提示条；
  脚本 `onerror` 说明可能是 Key/白名单/额度；地图彻底起不来时用 `.map-picker__mask`
  把原因铺在画布上，不只留一行小字。
- 该约定已写进 `AGENTS.md`「安全与配置提示」，新增外部服务（OSS、短信等）照此补码表。

- 需求：检测点按距离排序并显示距离、高亮选中；按钮「查询可约时段」→「预约检测」；

- 后端：`QuoteReq` 加 `stationId`。传了就按用户选择，但仍校验**站点启用 + 承接该车型 +

  不传走原 `matchStation` 自动匹配，旧前端不受影响。

  校验时段（UTC → 上海时间），配置缺失或格式坏时放行。
- 前端：`visibleStations()` 本来就返回 lng/lat/businessHours/serviceRadiusMeter，够用，
  不用加接口。距离用直线距离（haversine），不是驾车距离；定位失败退回服务端顺序，
  且默认选第一个，不阻塞下单。
- **「立即上门」是映射到最近一个可约班次**，不是真正随叫随到：核价与下单仍以

  真即时上门，需要后端支持 slot 可空 + 派单规则改造。

- 小程序模板兼容性：不要在模板里用 `String()` 之类全局调用（改用方法 `isPicked`），

- `toDate()` 已处理「裸 LocalDateTime 补 Z」，营业时间判断直接 `getHours()` 就是北京时间。

## 上门时间改为自由选择（commit c721258 / ef9801b / 63c9b94）
- 需求变更：不要按检测点班次挑，要像日历一样选到具体某天某时（如 2026-12-01 10:35），
  只限制在营业时间内。
- 数据：`vi_quote` 加 `pickup_at datetime(3)`（UTC），`pickup_slot_id` 放宽为 NULL；
  `vi_order.pickup_starts_at/ends_at` 本来就有，不用改。
- 后端：`QuoteReq.pickupAt`（上海时间 `yyyy-MM-dd HH:mm`）优先于 `pickupSlotId`：
  校验 ≥ now+30min、落在 `businessHours` 内；不占班次容量。
  建单按 quote 有无班次分两支：有则 `holdQuota` 占容量、起止取班次；无则起止取
  `pickup_at`，结束 = 开始 + 30 分钟（派单提前量仍按 pickupStart 推）。
- 前端：面板改成「立即上门 + 日期 picker + 时间 picker + 确定」。时间选择器的
  start/end 直接夹成 `08:00`~`17:59`（打烊前一分钟，避免选到 18:00 被 `hour < endHour` 判越界）。
  立即上门 = now+30min 向上取整到 5 分钟。换检测点重置为立即上门。
- **不要在本地时间串上调用 `toDate()`**：它给无时区串补 `Z` 当 UTC，会整体偏 8 小时。
  用严格正则 `yyyy-MM-dd HH:mm` 手工 `new Date(y,m,d,h,mi)`。
- 业务影响：自由时间不占班次容量，等于绕开了原来的 PICKUP 配额；若要控峰值，
  需要另做「按小时容量」限制（尚未实现）。
- 坑：`git commit -m` 正文含英文双引号会被 shell 提前闭合，后面的内容被当成文件路径
  （`did not match any file(s) known to git`）。含引号/反引号一律写消息文件后 `git commit -F`。


## 代驾费用试算恒为 ¥0.00（commit e7c6862）
- 现象：代驾费用规则 → 试算 10 公里，结果永远「本次试算应付 ¥0.00」。
- 根因：前端读错返回字段。`LedgerService.trialFee` 返回的是 `amountFen`，
  前端写的是 `res?.feeFen ?? res?.totalFen ?? 0`，两个字段都不存在 → 恒落到 0。
  **后端算法正确**：4000 + ceil((10000-8000)/1000)×500 = 5000 分 = 50 元。
- 修复：改读 `amountFen`，并展示拆分（基础费 + 超出里程 × 单价），方便当场核对。
- 本地规则参数（`vi_driver_fee_rule.pricing_json`，核算基准）：
  `NORMAL_RETURN` baseFen=4000 / includedMeters=8000 / unitMeters=1000 / unitPriceFen=500；
  `CANCEL_RETURN` baseFen=2000 / unitPriceFen=0。
- 教训：这类「前端字段名猜错」不会抛错，只会静默显示 0；先看 Network 的实际响应字段，
  别从 UI 反推。

## 提交信息里的反引号会被 shell 吞掉
- `git commit -m "...\`res?.feeFen\`..."` 在 Git Bash 下反引号被当命令替换，
  正文那段直接消失，还会打印 `command not found`。
- 规避：正文含反引号或 `$` 时，用 Write 写消息文件，再 `git commit -F <file>`
  （这次用 `--amend -F` 修正过）。

### 跨机型约束（小程序 WebView 真实限制，别写回去）
- **`inset: 0` 不能用**：iOS 14.5 以下不支持，遮罩会变 0 尺寸、弹层点不开 → 写四条边。
- **flex `gap` 不可靠**：部分安卓 WebView 不支持，会整排挤在一起 → 间距用 margin。
- **安全区双写**：`constant(safe-area-inset-*)`（iOS 11）+ `env(...)`（11.2+）。
- **箭头别用「›」字形**：不同机型字体宽高不一，容易被裁或偏移 → 两条边线 + rotate(45deg)。
- `navigationStyle: custom` 的页面（登录）必须 `calc(120rpx + env(safe-area-inset-top))`。
- 尺寸全部 rpx（750 基准），小屏（320）用 `@media (max-width: 340px)` 收边距。

### 下拉刷新的坑
- 4 个页面写了 `onPullDownRefresh`，但 `pages.json` 从未开 `enablePullDownRefresh`，
  真机上永远不触发。**新增会调用它的页面必须同步在 pages.json 打开**。

### 视觉验证方法（无需真机/开发者工具）
1. `npm run build:h5`（uni 的 H5 产物，view→div，布局与 WXSS 基本一致）；
2. `python -m http.server` 起静态服务；
3. `npx playwright screenshot --channel=msedge` 截图（playwright 浏览器未装时用系统 Edge）；
   需要登录态/数据时用 node 脚本 + `page.route('**/api/**')` 造 mock，
   注意 `.env` 的 `VITE_API_BASE` 带 `/prod-api` 前缀，匹配前要 `pathname.replace(/^\/prod-api/,'')`。
4. 构建到已有目录会被 safe-delete 拦（>50 文件），用 `UNI_OUTPUT_DIR=dist/build/h5b`
   换目录，`rm -rf` 同样被拦，清理用 python `shutil.rmtree`。
