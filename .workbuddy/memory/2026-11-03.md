## 后台数据权限改为多部门任职（提交 5410e0e）

- 原实现 `DeptScope.scopedDeptId()` 只读 `sys_user.dept_id` 主部门，且只看 `isAdmin()`，
  完全没读 `sys_user_dept` 与角色 `data_scope`。后果：`ry`（主部门 105，角色自定义授权 100/101/105）
  的业务数据全为 0（订单都在 dept 100），而符合规范的应见 33 条。
- 现改为 Spring 组件，委托框架 `IDeptScopeService.resolve(loginUser, permission)`：
  超管或 data_scope=ALL → 返回 null（不限制）；DEPT → 任职部门；DEPT_AND_CHILD → 展开下级；
  CUSTOM → `sys_role_dept`；解析为空直接 403（fail-closed）。
- 两套语义必须分开用，混用会越权或漏数据：
  - `visibleDeptIds()`：列表可见范围（可含下级）→ 订单/车辆/售后/统计/看板
  - `assignedDeptIds()` / `coversAssigned()` / `requireAssigned()`：记录归属是否属于我（精确）
    → 第三方配置详情、线下付款核实
  - `writeDeptId()`：写入用它，请求值必须在任职范围内，未指定落主部门
- Mapper 侧：17 个查询的 `@Param("deptId") Long` 改成 `@Param("deptIds") List<Long>`，
  SQL 由 `dept_id IN (SELECT ... WHERE dept_id = #{deptId} OR FIND_IN_SET(...))` 改为
  `dept_id IN <foreach>`；**展开统一在 Java 做**，SQL 里不再重复相关子查询，保住索引。
  注意 `AdminMapper`/`OrderMapper`/`VehicleMapper` 里的子查询是跨行书写的，批量替换要能容忍换行。
- `IntegrationMapper` 的 15 个 `deptId` 参数**故意保持单值**：路由/档案解析是"某个部门的那条配置"，
  改成集合会改变精确优先、全局兜底的语义。

## 第三方真实凭据联调（支付/短信/订阅）代码侧准备

后台三套配置入口要分清，别再混：
- **系统设置**（menu 2113，`/rongli/inspect/config/*`）：`rongli.pay.*` 管真实下单与退款
  （`BookingService` 走 `PayConfigService.settings()`，`NotifyService` 回调验签同源）、
  `rongli.sms.*` 管验证码短信、`rongli.mini.appId/appSecret` 管登录+手机号+订阅 token。
- **第三方服务**（menu 2240，`/rongli/integration/*`）：V6.4 profile/revision/template/route，
  只管业务事件通知（4 个事件），必须发布才生效。
- 同场景两套都配会**重复推送**；推荐只用 V6.4 那套，把 `rongli.subscribe.enabled` 关掉。

本次修掉的真实联调阻塞项：
- `SmsClient` 阿里云分支声明 `SignatureMethod=HMAC-SHA1` 却用 HmacSHA256 签名 → 真实 AK 必报
  `SignatureDoesNotMatch`。已参数化算法（腾讯 TC3 仍 SHA256）。
- `rongli.wechat.mock` 原本只能改 yml 并重启，导致凭据填了也不生效。现 `WechatMiniClient.isMock()`
  优先读 `sys_config:rongli.mini.mock`，可用 `PUT /api/admin/config/readiness/mock` 切换（写前校验
  AppID/Secret，避免切成 503）。`AuthService` 里那个从未生效的同名 `@Value` 已删。
- `AuthService` 登录 appId 改为「`rongli.mini.appId` → yml `rongli.wechat.appId` → 开发号」，
  否则真实模式仍用 `wxdev...` 会 `invalid appid(40125)`。
- `NotificationDispatchService` 订阅跳转页改为兼容 `pageRoute`/`page`：模板发布写的是前者，
  发送端原来只读后者 → 消息能到但点开没有落地页。
- 新增 `WechatPayClient.fetchPlatformCertificates()` + `PayCertService` +
  `AdminPayCertController`（`/api/admin/config/payment/platform-cert[/refresh]`，`persist=true` 落库
  `platformCert`+`platformSerialNo`）：平台证书不再手工粘贴，轮换后重跑即可。
- 新增 `ChannelReadinessService` + `AdminChannelReadinessController`：
  `GET /api/admin/config/readiness?probe=true` 聚合支付/小程序/短信/订阅/回调五块，
  回调探测用 GET（拿到任何状态码即"可达"），只读不发消息。
