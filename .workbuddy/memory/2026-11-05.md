## 用户文件全部去本地化（commit `3f83050`）

**改法**：

  bean，统一经 `SpringUtils.getBean(OssFileService.class)` 转发，历史调用点零改动。
- Excel 导出改 `ByteArrayOutputStream` 写内存后上传，不再落 download 目录；
  `/common/download`、`/common/download/resource` 改为从 OSS 读流。
  `checkAllowDownload` 要用 `FileUtils.getName(url)` 取最后一段，否则完整 URL 带 query 会被判非法。
- `RuoYiConfig` 删 `profile` 与 `getProfile/getUploadPath/getAvatarPath/getDownloadPath/getImportPath`；
  `application.yml`、`application-prod.yml` 去掉 `ruoyi.profile`；
  `ResourcesConfig` 去掉 `/profile/**` 的 `file:` 目录映射（留着会指向 null）。
- **新增 `/profile/**` 兼容层** `ProfileResourceController`：历史数据里 `/profile/upload/x.png`
  仍能显示，但内容从 OSS 按 key 取。404 用 `setStatus`，不要 `sendError`（会转派 `/error` 变 200+401）。
- 备份脚本去掉 upload 目录打包；部署文档目录规划、验收清单、排障表同步。

**验证**：全量 `mvn compile` + `package` 通过；18080 起实例，`/api/common/session` 401、

**遗留**：生产 Bucket 必须关闭「阻止公共访问」，否则 `public-read` 上传报 AccessDenied。

## 15:05 内置超管保护：策略不动，只修实现

- 现象：admin（user_id=1）在用户管理里任何修改都被拒「不允许通过业务接口操作最高平台管理员」；
  连**个人中心改自己的密码**也报同一条错误。
- 定性：目标保护是**有意设计**（`isAdmin()` 硬编码 `1L`，不读配置、不读角色，天然排除配置错误；
  与操作者身份无关，排除权限不足）。缺的是实现层。
- 根因：`lockAndCheckTarget` 把「锁行」和「目标能不能被业务接口改」揉在一起——
  1) 超管判定在 `protectPlatform` 之前**无条件**抛出，`changeOwnPassword` 传 `false` 无效，自助改密误伤；
  2) 判定在 `target` 赋值前抛出，catch 拿到 null → 失败审计 `target_user_id` 恒 NULL（审计 11/12）；
  3) `updateDepartments/updateRoles/changeRoleForUsers` 的 `!isAdmin() && 改自己` 是走不到的虚假承诺；
  4) 策略拒绝用 `ServiceException` 默认 code=500，前端当系统故障弹红条。
- 改法：拆 `lockTarget`（只锁行）+ `checkTargetWritable`（只判策略）+ `lockSelfTarget`（仅本人，
  不受超管保护约束）；自助改密走 `lockSelfTarget`——凭据维护不是管理动作，和个人中心改资料同一条旁路，
  否则超管只能改库、反而丢审计。策略拒绝统一 `new ServiceException(msg, 403)`；批量入口记录当前
  target 便于失败审计；前端 `isBuiltinAdmin()`（Number 比较，防 Long 序列化成字符串）禁用超管行状态开关。
- 实机验证（8080 + devtools 自动加载 `target/classes`）：
  - `PUT /system/user` userId=1 → code=403 + 新文案；审计 13 有 `target_user_id=1` 与 before 快照
  - 个人中心改密 admin123 ↔ 临时密码往返均 200，审计 14/15 `USER_PASSWORD_CHANGE_SELF SUCCESS`
  - admin 改 userId=2 → 200（审计 18），未误拦
- 运维提示：本地后端是 **IDEA + devtools**，`mvn compile` 写 `target/classes` 后会自动重启，
  可直接对该实例做接口验证；MySQL 实际监听 **3307**（3306 未起）。
- 数据侧遗留（未动，属配置口径非缺陷）：`admin.management_scope` 仍是 `DEPT`，全库无 PLATFORM 账号，
  第二层「平台账号仅最高管理员可操作」目前空转；超管已由第一层覆盖，暂不回填。

## 15:30 头像裁剪：jpg 被拒 + 旧头像不显示

- 现象①：选 `.jpg` 上传被拒「后缀不正确」；现象②：打开「修改头像」裁剪区空白、右侧预览也空，
  但页面上那张头像正常显示。
- 根因①：`vue-cropper` 固定输出 PNG（`options.outputType: "png"`），但 `FormData` 沿用了用户选的
  原始文件名 → 后端收到「PNG 字节 + .jpg 后缀」，`FileUploadUtils.assertImageSignature` 按魔数判不符；
  而抛出的是 `InvalidImageExtensionException`，文案写死了「后缀[x]不正确」，把「内容与后缀不符」
  说成「后缀不支持」，才让人误以为传错了格式。**裁剪类上传千万别用原文件名**。
- 根因②：`vue-cropper` 加载图片会设 `img.crossOrigin = "Anonymous"`（要读 canvas 像素），
  OSS 直链**没有 `Access-Control-Allow-Origin`**（桶未配 CORS），跨域图在 canvas 里加载失败；
  普通 `<img>` 不需要 CORS，所以「图片看着好好的，只是裁剪框空的」。
- 修法：前端 `avatarFileName(blob)` 按 MIME 重命名；裁剪器改用同源 `/dev-api/profile/<key>`
  （后端 `ProfileResourceController` 从 OSS 读流返回，GET 已 permitAll），绕开 CORS 不用改桶配置；
  后端在认得出真实类型时抛专门文案，认不出仍按原样拒绝。
- 实测：无头 Chrome 里 OSS 直链 + crossOrigin → ERROR，`/dev-api/profile/<key>` → loaded 200x200；
  接口侧 PNG 字节改名 .jpg → 新文案，文本伪装 .png → 仍拒绝。
- **环境坑（重要）**：本地 8080 是 IDEA 跑的 devtools 实例，`mvn compile` 重写 `target/classes`
  与 devtools 重启会打架——rongli 的 class 正在被覆盖时触发重启 → `NoClassDefFoundError:
  com.xinyi.rongli.common.support.ApiException`，整个 Web 上下文起不来。**改后端先停应用再编译**，
  或者编译完再手动重启，别在应用运行时编译。
- 另一个坑：本机 shell 有 `http_proxy=127.0.0.1:13863`，curl 打 127.0.0.1:8080 会被代理转一手
  返回 502，**本地探活一律加 `--noproxy "*"`**。

## 超管权限重构：从"一律禁写"改为"仅最高管理员可写"（策略调整）
- 问题：`checkTargetWritable` 对 `user_id=1` 一律 403，而最高管理员又只有 admin 一人、
  且不能改自己 → 昵称/手机号/角色/部门/代重置密码全部变成**死字段**。
- 新口径：**最高管理员 = 内置账号(user_id=1) 或 持有 role_id=1**。判定收敛到
  `ISuperAdminService`（新增），以下几处不再硬编码 `SecurityUtils.isAdmin()`：
  `SysPermissionService`（`*:*:*`）、`SysMenuServiceImpl`（全部菜单）、`DeptScopeServiceImpl`
  （resolve / checkDeptAccess / checkUserFullAccess）、`DataScopeAspect`、`SysUserServiceImpl`
  （checkUserDataScope）、`SysRoleServiceImpl`、`SysDeptServiceImpl`、`UserImportServiceImpl`、
  `SysUserController`（authRole 目标侧）。
  **踩坑**：只改 Service 层不够——委派的超管能过 `isHighestAdmin()` 却过不了 `@PreAuthorize`，
  因为 `*:*:*` 只给 userId=1；菜单与数据范围同理，会表现为"有角色但没权限/列表 0 条"。
- 放开：资料（昵称/邮箱/手机/性别/备注）、角色、部门、代重置密码 → 仅最高管理员，必填原因+审计。

  **移除超级管理员角色**（禁止，含批量授撤与导入覆盖）。
- 解死锁：普通管理员仍不能改自己的部门/角色，**最高管理员可以**；代重置密码对本人一律禁止。

## 会话失效分级：资料字段不再踢人（体验修复）
- 定位：`SysProfileController.updateProfile` 本来就不 bump 版本；真正"改资料被踢"的是
  用户管理页"修改"按钮 → `updateUserBase`，它把昵称/邮箱/手机/性别/备注/岗位打包成一次
  "授权变更"无条件 `bumpVersion`（`auth_version+1` + outbox + afterCommit 删 Redis token）。
- 结果：管理员改别人昵称 → 对方被强退；最高管理员改自己昵称 → **自踢**，下一个请求 401。
- 改法（commit 40b2ee5）：`updateUserBase` 不再递增版本；`SessionInvalidator` 新增
  `refreshUserProfileSnapshot(userId)`，提交后按用户 token 索引逐个回写展示字段，
  **用剩余 TTL**（`getExpire` 秒）而不是 30 分钟，避免顺手续期；不动 roles/permissions/authVersion。
