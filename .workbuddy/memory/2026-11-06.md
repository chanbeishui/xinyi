# 2026-11-06

## 集成凭据页「发布生效」永远点不动（B53 小程序公共凭据）
- 现象：填好 AppID/名称/启用开关后，"发布生效"始终禁用；顶部持续报
  `appId 请填写小程序 AppID`、`appName 请填写小程序名称`、`enabled 请确认应用启用状态`。
- 两个原因叠加，缺一不可：
  1. **页面顶部的 issues 是服务端对"已保存草稿"的校验结果**（`profileView` 里
     `IntegrationRules.validate(kind, draftConfig, slots, true)`），不是对当前表单。
     内容只在浏览器里没保存时，草稿仍为空 → 三条 ERROR 照旧。`enabled` 那条
     说明草稿里是 `false`，即开关的改动同样没落库。
  2. **前端断链（真 bug）**：`ConfigShell.vue` 的 `load()` 无条件 `draftRev = null`，
     而 `saveDraft()` 成功后立刻 `await load()`。刚拿到的草稿版本被自己清掉 →
     「校验」按钮 `:disabled="!draftRev"` 变灰 → `checkResult` 永远为空 →
     「发布生效」`:disabled="!checkResult"` 永远禁用。线上这个页面**根本走不到校验**。
- 修法（commit c0adcbd）：
  - `load()` 用 `detail.draftRevisionId` 恢复 `draftRev`（后端 `profileView` 根节点有这个字段）；
  - `runCheck()` 以 `detail.draftRevisionId` 为准，没有草稿时给提示而不是静默 return；
  - 发布条件收紧为 `checkResult && status !== 'FAIL'`，并用 tooltip 说明卡在哪一步；
  - 按钮外包 `<span>` 才能让 disabled 状态触发 tooltip（Element Plus 的已知限制），
    同时要自己补 `margin-left: 12px`，否则相邻按钮间距丢失。
- 校验状态取值只有三种：`FAIL` / `PASS`（LOCAL）/ `PARTIAL`（非 LOCAL）。
- **环境错位提醒**：本机 `xinyi` 库里 `vi_integration_profile` 只有 `PAYMENT_POLICY`
  和 `WECHAT_PAY`，没有 `WECHAT_APP` 记录，说明用户操作的是另一套环境；
  代码改在仓库里，要在他那套环境重新构建前端才生效。
- 该页面的字段定义在 `views/rongli/integrations/wechatApp.vue`（`fields`/`secretSlots`/`defaults`），
  通用外壳是 `components/ConfigShell.vue`，所有 kind 共用同一套发布流程。
